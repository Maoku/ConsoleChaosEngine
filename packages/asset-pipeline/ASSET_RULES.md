# 世代別アセット共通規則

この文書は共通素材生成ルールの正本です。具体的な色数予算、版面、素材名は各ゲーム側に置きます。

1. ベース素材は 1 つでよいが、全世代への単純な同一縮小は禁止する。
2. 世代差は解像度、色空間、色数、palette 区画、alpha、格子など実際の能力制約から作る。
3. ハードウェア能力値をゲームの recipe へ書き写さず、Engine profile から導出する。
4. 素材単位の予算と layout はゲーム側へ置き、根拠を comment または文書に残す。
5. 調整数値は recipe、処理順は builder に置く。
6. 足りない姿勢・表情・動きの状態を既定動作として推測生成しない。
7. source に存在しない姿勢、表情、目パチ、髪や衣装の動きを作るために、shear / warp / 局所変形を
   使用しない。例外は、ユーザーがその変形方式を明示的に指示した場合だけとする。
8. 「左右に揺らす」「目パチさせる」などの機能要求だけを、shear / warp の許可と解釈しない。
   必要な状態を表す source frameを用意するか、sourceの意味を変えないruntimeの平行移動・回転などで表現する。
9. 動く光、影、合成など実行時に意味を持つ表現を素材へ焼き込まない。
10. 原画、recipe、出力の対応を deterministic manifest で追跡できるようにする。
11. 未知の設定、素材 ID、世代、未対応画像形式を黙って無視しない。
12. 寸法だけでなく色数、alpha、palette、区画、runtime 配置との一致を CI で検査する。
13. 新しい汎用処理は、少なくとも 2 つの実利用または明確な次の利用先がある場合だけ追加する。
14. 目視確認が必要な品質と、CI で機械検査できる制約を区別する。

## 幾何変形の境界

`crop`、余白調整、世代解像度への `resample`、tile/gridへのsnap、色・alpha・palette量子化は、
sourceの意味を保った世代変換として扱います。一方、次はsourceにない内容を作る意味的変形であり、
ユーザーから方式まで明示されない限り採用しません。

- body shearで別の姿勢や傾きを作る
- 顔や目の局所warpで表情、開眼、半閉じ、閉眼を作る
- 髪、ポニーテール、衣装、手足のwarpでanimation frameを作る
- 1枚のsourceから変形parameterだけを変えて、別のkey poseが存在するように見せる

ユーザーがshear / warpを明示的に指示した場合も、次を満たします。

- 対象asset、変形箇所、意図、parameter、処理順をゲーム側のrecipeまたはprovenanceへ記録する
- 生成済みPNGを直接編集せず、builderから決定的に再生成できるようにする
- 意図しない輪郭破損、pixel hole、pivotずれ、世代間差を自動検査と目視確認の両方で確認する
- game固有の変形を共通packageへ追加せず、汎用化は規則13の条件を満たす場合だけ検討する

共通 package へゲーム固有の人物、scene、謎、URL、意味 palette を追加しません。意味判断が必要な場合は、
ゲーム側から palette resolver callback を渡します。
