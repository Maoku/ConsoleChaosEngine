# 4ステージデモ 実装・検証記録

更新: 2026-10-02。対象は [実装計画](FOUR_STAGE_IMPLEMENTATION_PLAN.md) と [企画書](../FOUR_STAGE_DEMO_PLAN.md)。M0〜M4の機能を実装し、M5の自動検証・試遊記録を整備した。**初見15〜30分、理解度、ゲームパッド実機での操作感は人の試遊待ち**。

## 遊ぶ・調べる

リポジトリのルートで `npm run dev --workspace apps/console-chaos`。既定URL `/` が新キャンペーン。

- 「最初から」でステージ1・CH 1を開始。「続きから」は成果・CP・道seed・回転盤の安全な位相を復元。
- 移動 WASD/矢印、ジャンプ Space、世代 1〜4 または Q/E、ヒント H、CPへ再試行 R、タイトルへ Escape。
- `?stage=demo_stage2&playtest=0` 等で各v2ステージを単独起動。単独起動はキャンペーン保存・次ステージ遷移を含まない。
- `?level=area1`、`?level=mini`、`?level=puzzle_lab` と既存 `?scene=…` は旧検証経路。
- `/?playtest=1` は新デモの試遊記録を有効化。PでJSONを取得。通常起動ではこの記録を収集しない。

保存キーは `chaos.campaign.four-stage.v1`。互換version/content revision、stage順序、成果、seed、停止位相を検査する。CPだけが見つからない場合は同じstageのspawnへ戻す。storage拒否時は通知してプレイを続ける（ブラウザでも読取・書込を拒否させて起動と移動を確認済み）。新規開始はsession再生成、落下・RはCPの一時状態復旧。

## 技術の採用結果と限界

CH 2の庭園は、旧XZ公転から、固定横視点のXY回転盤へ変更した。盤は実際の `affineSurfaces` を使用し、島中心とUVを同じposeから計算する。回転＋最大3%の拡縮、720tick周期。CH 2が安定し、区間の近くにいる間だけ進む。他CH・切替中・区間外では停止。足場は水平AABBを維持し、ground anchorが島を指す乗客だけを物理前に運ぶ。空中の近接吸着はしない。固定視点の区間では四世代の操作方向を横視点にそろえ、主人公が画面内に収まる距離でカメラを切り替える。盤中心は初回tick前から配置座標を持つ。盤の素材は既存の格子で、新規の円形透明合成やengine API拡張は追加していない。

継ぎ目は既存の殻モデル全体を消す方式を使わず、見える板と周囲の壁を別entityにした。開口板の表示とcollider.solidを同じ状態で切り替える。第3世代の頂点揺れ・affine texture表現は既存rendererから引き継ぐ。継ぎ目の開閉自体はappの能力ルールで、GPUのソート結果を読み取って判定する方式ではない。

光は半径7の球状点光源を描画と判定で共有し、`max(0, 1 - distance / 7)^2` が0.12以上で刻印が反応する。接触しにくい岸の外へ刻印を置き、照らした後は明るい状態を保持する。向き・遮蔽・精密な影は扱わず、光を遮る物を配置しない。

第1ステージの3Dの細い道は正当な別解として保持。最終装置の合流成果はCH 1の接続を要求し、中継は実際の搬送、内部復旧は開口からの到達、照明は距離条件を要求する。世代の訪問回数では達成しない。成果を一つ欠く場合はgoalへ接触してもクリアできない。

実Chromium/WebGL検証の再実行:

```bash

npm run verify:browser:demo --workspace apps/console-chaos
```

`tools/verify-demo-browser.py` はGameHostへ実キーボードイベントを渡して4ステージを進める。playerのワープ・成果の注入は使わない。タイトルの停止、橋・裏側の成果を保存してreloadから再開、回転面command、途中画面・次へ・結末を検査する。結果、WebGL canvas画像、UIテキストは、リポジトリ規約に従い非追跡の `Docs/measurements/four-stage-demo/` に出す。固定tickで正解を知ったルートを自動操作するので、ここでの秒数を初見の所要時間に使わない。

## M5: 人の試遊で確認すること

1. 既存の正解を知らない人に、キーボード・ゲームパッドの両方で試遊してもらう。最初から全編の所要時間と段階ヒントを観測する。
2. 各stage後に「なぜ切替で進めたか」を本人の言葉で聞く。通常の結末画面には進行役用の質問を出していないため、説明理解は別の記録へ残す。
3. 格子の回転・拡縮と乗り移りの関係、CH 1の群れの裂け目から灯を読めるか、CH 3の入口の発見、CH 4の刻印の光の読みやすさを確認する。
4. 15〜30分・中心20〜25分に収まるよう、道の長さ・足場幅・端子位置・55/50/45秒のヒント遅延を実測から調整する。

試遊JSONの集計:

```bash
npm run playtest:report:demo --workspace apps/console-chaos -- /path/to/tester-01.json /path/to/tester-02.json
```

stage/配置ID/種類別の達成時刻、CP、切替、落下、ヒント、滞留、入力方式を記録する。入力列や個人名は収集しない。全編の中央値には、4stageを順に完了し、復元済み成果のない記録だけを使う。記録はメモリ上にあるため、reload以前の試遊時間は合算されない。reloadを含む記録は時間目標の判定から除外する。
