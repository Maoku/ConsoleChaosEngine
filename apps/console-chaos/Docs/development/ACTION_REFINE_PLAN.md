## 1. 改修後の到達状態

1. 第2世代を含む全世代で、滝の模様が画面上から下へ流れる
2. `area1.json` に配置された全 6 謎が、名称と 4 段階ヒントを必ず持つ
3. クリア時アンケートに `F-1 色の潰れ` のような「ID + 謎の名称」を表示する
4. 第3・第4世代のジャンプが `Regular_Jump` を使い、離陸・滞空・着地を 1 クリップで再生する
5. 新しいプレイは必ず第1世代（内部 ID `FC`、表示 `CH 1`）から始まる
6. タイトル画面を 10 秒間操作しなければデモを開始し、4 世代を 2 周して F-1 の蔦を渡った後にタイトルへ戻る。戻った後も、再度 10 秒放置すれば同じデモを開始できる

## 2. 現状調査

| 要望 | 現在の実装 | 改修が必要な理由 |
|---|---|---|
| 第2世代の滝を下向きにする | `render/material.ts` の `waterfall.uvScrollY` は `0.35`。Renderer はこの値を時刻に掛けて UV に加算している | 正の UV 移動により、模様が画面上では逆向きへ動く。値は全世代共通なので、世代 ID の分岐を追加せず向きを正す必要がある |
| 全謎にヒントを対応する | `area1.json` と `HINT_COPY` は現時点ではともに 6 件だが、未登録 ID は共通文へ黙ってフォールバックする | 静的調査では「4 件だけ」の状態を再現できないものの、対応漏れを検出するゲートが無い。同種の欠落を確実に防ぐ必要がある |
| アンケートへ謎名を出す | `debug/playtest_flow.ts` の `askRow` は `puzzleId` だけを表示する | 試遊者・進行役が ID と内容を対応づけにくい |
| `Regular_Jump` を使う | 第3・第4世代とも `360_Power_Spin_Jump` を参照し、空中である限りクリップ時刻を進め続ける | 新クリップへの参照変更だけでは、空中で末尾から先頭へループし、接地した瞬間に着地部分が打ち切られる |
| 第1世代で開始する | `initialGenerationForScene('mini')` は `PS1` を返す。`Session.reset()` は現在の世代を維持する | 初回だけでなく、クリア後の「もう一度」やデモ開始時も開始世代を統一する必要がある |
| 10 秒放置デモ | `debug/playtest_flow.ts` は開始・プレイ・終了の 3 状態だけで、タイトルへ戻す API、放置タイマー、自動入力経路が無い | UI 状態、決定的な自動操作、プレイテスト記録の除外を追加する必要がある |

### 2.1 謎の正規名称

`GAME_PLAN.md` §6 と現在の垂直スライスを正本として、表示名を次に固定する。

| ID | 表示名 |
|---|---|
| F-1 | 色の潰れ |
| F-2 | ちらつきの隙間 |
| S-1 | 回る床 |
| P1-1 | 裏側 |
| P1-2 | ソートの破れ |
| P2-1 | 暗闇と松明 |

### 2.2 `Regular_Jump` の実データ

両 GLB の `Regular_Jump` は同じ時間構造を持つ。

| 項目 | 値 |
|---|---|
| キー数 | 58（30 fps） |
| クリップ長 | 約 1.933 秒 |
| 19 フレーム目 | 約 0.633 秒 |
| 20 フレーム目 | 約 0.667 秒 |
| 21 フレーム目 | 約 0.700 秒 |

GLTF はフレーム番号ではなく秒を持つため、設定には `sourceFps: 30` と
`airborneFrames: [19, 21]` を明示し、1 始まりのフレーム番号から時刻へ変換する。

## 3. 設計方針

### 3.1 謎の表示情報を 1 か所へ集約する

`src/gameplay/puzzles/catalog.ts` を新設し、謎 ID ごとに次を持たせる。

```ts
interface PuzzleCatalogEntry {
  name: string;
  hints: {
    stage3: string;
    stage4: string;
  };
}
```

- `hints.ts` は段階 3・4 の文面をこの表から取得する
- クリア時アンケートは同じ表から名称を取得する
- 段階 1・2 は従来どおり共通文と `requiredGenerations` から組み立てる
- プレイテスト JSON は後方互換性のため `puzzleId` を維持し、表示時だけ名称を解決する
- `check:levels` で、配置された全 `puzzleId` にカタログ項目と非空の段階 3・4 があることを検査する

本番の防御用フォールバックは残してもよいが、通常ビルドへ到達する前に CI を失敗させる。
「未知の謎が共通ヒントで動いてしまう」状態を正常系として扱わない。

### 3.2 世代差は既存プロファイル境界を守る

- 滝の向き修正のために `generation === 'SFC'` の分岐を追加しない
- 初期世代の決定は `initialGenerationForScene` と新規ラン開始処理へ集約する
- デモの世代切替は通常と同じ `GenerationController.request()` を通す
- パズル・物理・レベルデータにはデモ専用分岐を追加しない

### 3.3 デモも通常のゲームを操作する

デモはプレイヤー座標を書き換えず、通常の `ConsoleChaosActionSnapshot` を生成する。
その値を `app.ts` の固定更新前に注入し、通常と同じ `Session.tick()`、物理、パズル判定、チェックポイントを通す。

- タイトルの 10 秒は実時間で測る（ゲーム更新が停止しているため）
- デモ開始後の進行は固定ティックで測る（再現可能にするため）
- デモの完了は座標だけでなく `session.solved.has('F-1')` で判定する
- デモ中の解決数・ヒント・世代切替をプレイテスト記録へ保存しない

### 3.4 ジャンプの物理と見た目を分離する

ジャンプの高さ、速度、可変ジャンプ、接地判定は変更しない。
`presentation/frame.ts` が物理状態を読み、アニメーション時刻だけを次の状態機械で写像する。

```text
通常 idle / walk
  ↓ 上向きに離地
離陸 Regular_Jump 1〜18
  ↓ 19フレーム目へ到達
滞空 Regular_Jump 19〜21（空中で保持または反復）
  ↓ 接地
着地 Regular_Jump 22〜58（非ループ）
  ↓ 再生完了
通常 idle / walk
```

段差から落ちただけの場合は離陸を再生せず、19〜21 の滞空部から開始する。
着地中も操作と物理は止めず、見た目だけ着地部を最後まで再生する。

## 4. 改修タスク

### AR-01 滝の流れを下向きへ修正する

| 項目 | 内容 |
|---|---|
| 主変更 | `src/render/material.ts` の `waterfall.uvScrollY` を下向きになる符号へ変更する |
| 補助変更 | コメントを「UV の正方向」ではなく「画面上で下へ流れる」基準に直す |
| 自動検証 | `materialFor('waterfall')` と生成された `RenderMaterialCommand` の符号・値を固定するテストを追加する |
| 画面検証 | 同じ滝を第1〜第4世代で 1 秒以上観察し、模様の特徴点が下へ移動することを確認する |

第2世代を主受け入れ対象とするが、現在の値が全世代共通であるため、4 世代すべてを回帰確認する。
テクスチャ自体の上下反転や世代別コピーの作り直しは行わない。

### AR-02 全謎の名称・ヒント・アンケート表示を統合する

| 項目 | 内容 |
|---|---|
| 新設 | `src/gameplay/puzzles/catalog.ts` |
| 移動 | `hints.ts` の `HINT_COPY` をカタログへ統合する |
| ヒント | `composeHintTexts()` はカタログの段階 3・4と、レベルの `requiredGenerations` を合成する |
| アンケート | `askRow()` のラベルを `${puzzleId} ${name}` にする |
| レイアウト | 6 件が低い画面でも欠けないよう、アンケート領域に最大高と縦スクロールを設定する |
| データ互換 | `PlaytestRecord.puzzles[].puzzleId` は変更しない |

受け入れ条件:

1. `area1.json` の 6 ID がすべてカタログに存在する
2. 各 ID の段階 3・4が空でない
3. 段階 2 と `{channels}` は引き続き `requiredGenerations` から生成される
4. クリア画面に 6 件すべての「ID + 名称 + 可/否」が表示される
5. 未登録の謎をレベルへ追加したテストでは `check:levels` が失敗する

### AR-03 `Regular_Jump` を物理状態へ同期する

| 項目 | 内容 |
|---|---|
| 設定 | 第3・第4世代の `jump.animation` を `Regular_Jump` に変更する |
| 設定 | `sourceFps: 30`、`airborneFrames: [19, 21]`、`loop: false` をモデル用クリップ情報へ追加する |
| Presentation | 離陸・滞空・着地の状態とアニメーション時刻を保持する |
| Engine | `SkinnedMeshCommand` に後方互換な `loop?: boolean` を追加し、`sampleAnimation` へ渡す |
| アセット検証 | `player_model.test.ts` で `Regular_Jump` の存在、58 キー、19〜21 フレームの時刻を検査する |

受け入れ条件:

1. 第3・第4世代とも、離地時にフレーム 1 から始まる
2. 空中時間が長くてもクリップ全体を先頭へループしない
3. 空中では 19〜21 フレームの範囲外へ進まない
4. 接地後に 22〜58 フレームを 1 回再生してから idle / walk へ戻る
5. 第1・第2世代のスプライトジャンプ、ジャンプ物理、リプレイ結果は変わらない

### AR-04 新しいプレイを第1世代から始める

| 項目 | 内容 |
|---|---|
| 初回起動 | `initialGenerationForScene('mini')` を `FC` に変更する |
| デバッグ | `ps1` / `blend` など世代が目的のデバッグシーンは現在の開始世代を維持する |
| 新規ラン | 手動の「はじめる」「もう一度」とデモ開始時に、セッションをリセットして `FC` を要求する共通処理を使う |
| タイトル復帰 | デモ終了後はタイトルで隠れている間に `FC` へ戻す |

`R` キーのクイックリトライは「現在の見えを保ったまま試す」用途があるため、本計画では世代を維持する。
第1世代へ戻す対象は、初回起動と明示的に新しいランを開始する経路に限定する。

### AR-05 タイトル・プレイ・デモ・クリアの状態を明示する

現在の `PlaytestFlow` を次の状態で管理できる UI フローへ整理する。

```ts
type RunMode = 'title' | 'manual' | 'demo' | 'clear';
```

推奨する分担:

- `src/ui/game_flow.ts`: タイトル、10 秒タイマー、クリア画面、タイトル復帰
- `src/debug/playtest_flow.ts`: 手動プレイ時の記録・保存 UI を `game_flow` へ接続する薄いアダプタ
- `src/gameplay/demo.ts`: 固定ティックのデモ状態機械と自動アクション
- `src/engine-bootstrap.ts`: `RunMode`、Session、Generation、プレイテスト記録を接続する

タイトルの放置時間は定数 `TITLE_DEMO_IDLE_MS = 10_000` とする。次の入力をタイトル操作としてタイマーを 0 へ戻す。

- キーボード入力
- pointer / touch の操作
- ゲームパッドのボタンまたは deadzone を超える軸入力
- タブが非表示から復帰したとき

タブが非表示の間は時間を加算しない。バックグラウンドで 10 秒が経過しただけではデモを開始しない。

### AR-06 デモの固定シーケンスを実装する

#### 4.6.1 シーケンス

| デモ経過 | 動作 | 世代 |
|---|---|---|
| 0 秒 | セッションを初期化し、安全な開始足場内で往復を始める | 第1世代 |
| 5 秒 | 世代切替 1 | 第2世代 |
| 10 秒 | 世代切替 2 | 第3世代 |
| 15 秒 | 世代切替 3 | 第4世代 |
| 20 秒 | 世代切替 4（1 周完了） | 第1世代 |
| 25 秒 | 世代切替 5 | 第2世代 |
| 30 秒 | 世代切替 6 | 第3世代 |
| 35 秒 | 世代切替 7 | 第4世代 |
| 40 秒 | 世代切替 8（2 周完了） | 第1世代 |
| 40 秒以降 | 第1世代の 2D 投影を使って右へ進み、開始区画と F-1 の撚られた蔦を渡る | 第1世代 |
| F-1 解決後 | セッションをリセットし、タイトルへ戻して放置タイマーを 0 にする | 第1世代 |

「2 周」は `FC → SFC → PS1 → PS2 → FC` を 2 回完了した状態と定義する。
切替要求は 5 秒ごとに 1 回だけ出し、350 ms の通常トランジション中に要求を連打しない。

#### 4.6.2 自動移動

- 往復範囲は `start_floor_a` の当たり判定から安全余白を引いて求め、座標を複製しない
- カメラ向きが異なる第4世代でも同じワールド X 方向へ動けるよう、目標ワールド方向を現在のカメラ基底へ逆変換する
- 2 周後は `f1_pedestal` の位置をレベルデータから引き、X 方向へ移動する
- 完了条件は `session.solved.has('F-1')`
- 落下・復帰が発生した場合は第1世代でルートを再試行する
- F-1 へ進み始めてから 20 秒以内に解決できなければ、デモを終了してタイトルへ戻す。無限デモにはしない

#### 4.6.3 ユーザー操作と記録

- デモ中にキーボード、ゲームパッド、pointer / touch の操作を検出したらデモを中断し、タイトルへ戻る
- デモ中は `PlaytestLog.update()`、`keep()`、`markCleared()` を呼ばない
- デモ終了時に解決済みパズル、ヒント段階、チェックポイント、プレイヤー位置をリセットする
- ブラウザの音声制限を回避するための偽のクリックは生成しない。ユーザー操作前のデモが無音でも正常とする
- `?playtest=0` とデバッグシーンでは既存どおりタイトル／デモを無効化できる
- デモスクリプトは `area1` 専用とし、必要なアンカーがない別レベルでは開始しない

## 6. 実装順序と依存

```text
AR-02 謎カタログ ───────────────→ アンケート・ヒント検証

AR-03 Regular_Jump ─────────────→ Presentation / Engine 回帰

AR-04 第1世代開始 ──→ AR-05 RunMode ──→ AR-06 デモ

AR-01 滝 ───────────────────────→ 4世代の画面確認

全タスク ──────────────────────→ verify + 手動受け入れ
```

推奨順:

1. AR-02（表示情報の正本を先に作る）
2. AR-01（独立した描画修正）
3. AR-03（アニメーション修正）
4. AR-04（全ランの開始条件を固定）
5. AR-05（UI 状態を分離）
6. AR-06（分離した状態へデモを接続）
7. 全自動検証とブラウザでの受け入れ確認

実装目安は 5〜7 日。最も不確実性が高いのはデモの自動横断と、着地部の見た目の長さである。

## 7. 自動検証計画

### 7.1 ヒント・アンケート

- `area1.json` の配置 ID 集合がカタログ ID 集合に包含される
- 全配置 ID で `name`、`stage3`、`stage4` が非空
- `composeHintTexts()` が 6 件すべてで 4 文を返す
- レベルへ未知 ID を追加した fixture で `check:levels` が失敗する
- PlaytestRecord の JSON 形が変わらない

### 7.2 ジャンプ

- 両 GLB が `Regular_Jump` を持つ
- 両 GLB の滞空フレーム時刻が 19 = 0.633 秒、20 = 0.667 秒、21 = 0.700 秒と許容誤差内で一致する
- 空中を通常より長く保つテストでもアニメーション時刻が 19〜21 の範囲を越えない
- 接地後は 22 以降へ進み、完了後に idle / walk へ戻る
- 既存の `area1_full_run` を含む全リプレイの最終結果が変わらない

### 7.3 初期世代・デモ

- 本編 `mini` は `FC`、`ps1` デバッグシーンは `PS1` で開始する
- 9,999 ms の放置ではデモを開始せず、10,000 ms で 1 回だけ開始する
- タイトル入力でタイマーが 0 に戻る
- 300 固定ティックごとの切替先が `SFC, PS1, PS2, FC, SFC, PS1, PS2, FC` になる
- 2 周前は開始足場内に留まり、2 周後にだけ F-1 へ進む
- `F-1` 解決でタイトルへ戻り、再度 10 秒後に 2 回目のデモを開始する
- デモ終了後の Session が未解決・開始位置・第1世代へ戻る
- デモ中に PlaytestRecord が増えない

### 7.4 実行ゲート

npm --prefix apps/console-chaos run test:e2e
npm --prefix apps/console-chaos run check:levels

- §7 の検証がすべて成功する
- 既存のゴールデン、リプレイ、レベル検査、アセット検査を更新理由なく緩和しない
- 世代 ID による新しいゲームプレイ分岐を追加しない
- デモ用の座標直接書き換え、実時間によるゲーム進行、合成 DOM クリックが存在しない

### 8.2 画面ゲート

| # | 操作 | 合格条件 |
|---|---|---|
| V-1 | 第2世代で滝を 1 秒以上見る | 模様が上から下へ流れる |
| V-2 | 6 謎の近くで H を 4 回押す | 各謎で 1〜4 段階が表示され、3・4 はその謎固有の文面 |
| V-3 | area1 をクリアする | アンケートに 6 件の ID・名称・可否ボタンが欠けずに出る |
| V-4 | 第3世代でジャンプする | 離陸、19〜21 の滞空、着地が自然につながり、空中で先頭へ戻らない |
| V-5 | 第4世代でジャンプする | V-4 と同じ。モデルの向き・足元位置も崩れない |
| V-6 | ページを開いて開始する | 初期チャンネルが CH 1 |
| V-7 | タイトルで 10 秒放置する | デモが始まり、5 秒ごとに 2 周切り替わる |
| V-8 | デモを最後まで見る | 第1世代で蔦を渡り、タイトルへ戻る |
| V-9 | 戻ったタイトルで再び 10 秒放置する | 同じデモが再実行される |
| V-10 | デモ中に入力する | デモが中断され、タイトルへ安全に戻る |

## 9. リスクと対策

| リスク | 対策 |
|---|---|
| レベル調整でデモ経路が壊れる | 足場・台座の transform / collider を ID から取得し、F-1 解決を完了条件にする。`check:levels` でデモアンカーも検査する |
| 低フレームレートでタイトルタイマーが飛ぶ | 絶対時刻の差で測り、開始済みフラグで多重起動を防ぐ |
| デモが試遊データへ混入する | `RunMode === 'manual'` の場合だけ PlaytestLog を更新・保存する |
| ジャンプが接地時に不自然に止まる | 着地状態を Presentation が保持し、接地後もクリップ末尾まで非ループで再生する |
| 19〜21 フレームの解釈がモデル更新でずれる | fps・キー数・対象フレーム時刻をアセット検査で固定する |
| 滝修正が別世代を逆向きにする | 世代別分岐を作らず共通符号を修正し、4 世代の時間差画面を確認する |
| クリア画面が低い表示領域で切れる | アンケート一覧だけをスクロール可能にし、保存・再開ボタンを表示領域へ残す |

## 10. 対象外

- 謎そのものの成立条件、配置、難易度の変更
- ジャンプ速度・重力・可変ジャンプ・壁蹴りの調整
- 滝テクスチャの描き直し
- デモで F-1 より先を攻略すること
- デモのためのプレイヤー座標ワープ
- プレイテスト JSON への謎名の複製
- ブラウザの自動再生制限を回避する処理
- デバッグシーンおよび互換デモスクリプトの無い別レベルでの放置デモ
