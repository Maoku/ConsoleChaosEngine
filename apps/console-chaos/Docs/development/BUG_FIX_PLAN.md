# 不具合報告（2026.08.09）への修正計画（BR-01〜BR-05）

出どころは `Docs/development/BUG_REPORT.md` の 5 件。いずれも KV-02〜KV-07（背景の導入）と
T2-08（カメラ）の後に見えてきたもので、**骨格ではなく値と置き場の問題**である。

守るもの:

- 不変条件 I1（世界は 3D で 1 つ）／ I2（世代 ID の分岐は `profiles.ts` と `pipeline.ts` だけ）
- 決定 1（形は変えない。**色と背景だけで四つの世界を作る**）
- §11.1.1（汎用のパララックス機構・マテリアルグラフを作らない。**層は最大 2 枚のまま**）
- レベルデータは 3D の真実だけを持つ（§5.9）。見えの情報をレベルへ足さない

数値はすべて**画面で詰める前の初期値**である。確認は `window.__chaos` から 1 フレーム進めて
`readPixels` / スクリーンショットを撮る手（`memory/webgl-preview-cannot-verify-pixels`）で行う。

## 1. 原因（機械的に確認したこと）

### 1.1 共通の座標

2D 世代の画面は **横 8m ちょうど**（`internalWidth 256 / PIXELS_PER_WORLD_UNIT 32`）、
縦 7m（`orthoHeight = 224 / 32`）。背景シェーダの UV は画面幅あたり `repeat` 周するので、

```
床と同じ速さで流れる scroll = repeat / 8   （UV / m）
床と同じ速さで流れる scrollY = 1 / 7 ≒ 0.143（画面比 / m）
```

この 2 つが「ズレているかどうか」の基準になる。

### 1.2 BR-01 第1世代の背景（`profiles.ts:426`）

`far: { repeat: 3, scroll: 0.012, bottom: 0.26, height: 0.34 }`。
床と揃うのは `3 / 8 = 0.375` なので、**遠景は床の 1/31 の速さでしか流れていない**。
第2世代のためにある多重スクロールの値が、そのまま第1世代にも入っている。

縦も揃っていない。層は画面に貼り付いたままで、カメラが上下しても動かない。

絵の側（`tools/make-textures.ts` の `backdropFar`）は幅 128 の中に
奥 4 桁 + 手前 8 桁の塊を**隙間なく**並べている。これが `repeat: 3` で 3 回敷かれるため、
画面の地平が端から端まで建物で埋まる。

### 1.3 BR-02 第2世代の背景（`profiles.ts:479`）

`far: 0.010 / near: 0.034`。床速はそれぞれ `2/8 = 0.25`、`1.5/8 = 0.1875` なので、
**手前の雲でも床の 18%、奥の丘は 4%**。2 枚の比は 3.4 倍しかない。
横に歩いても層が分離せず、「多重スクロール」として読めない。
縦のパララックスは持っていない（ジャンプしても背景が動かない）。

### 1.4 BR-03 黒い床（`material.ts:116` / `renderer3d.ts:546`）

P2-1 の暗室は `dark()`（`ambient 0.05 / diffuse 0`）で「**持たない世代では文字どおり何も見えない**」
を作っていた（`p2_1_torch.ts:14`）。
これが成立していたのは、改訂前の背景が `pipeline.ts` の**黒クリア 1 枚**だったからで、
黒い床が黒に沈んでいた。

KV-02 で背景が全画面 1 枚になり、暗室にも空が描かれるようになった。
結果、ほぼ黒の床が**空を背にしたシルエット**として読める。

パズルの成立条件そのものは壊れていない（刻印は `dynamicLight` を持つ世代でしか反応しない）。
壊れたのは**見え**であり、P2-1 の体験の芯そのものである。

### 1.5 BR-04 第3世代のカメラ（`profiles.ts:510`）

`distance 4.5 / height 1.6 / targetHeight 0.3 / lookAhead 1`。
T2-08 で改訂前（9 / 3.2）の半分まで詰めたが、まだ引きが強い。
画角は 55° 固定（`camera.ts:36`）なので、**大きさは距離だけで決まる**。

### 1.6 BR-05 ブラウン管風表示の切替（`crt.ts:23`）

`CrtOptions.override`（プリセットの部分上書き）は**用意されているが誰も渡していない**。
`PipelineOptions` が受け取るのは `quality` と `glitchAmount` だけで、道が繋がっていない。
`src/ui/settings.ts` は T3-06 の空ファイルのまま。

モアレの出どころは 2 つある。

1. **蛍光体マスク** … `mod(gl_FragCoord.x, 3.0)`（`crt.glsl:65`）。
   CRT パスは出力解像度（960×720）で走るので、3 画素周期の縞が、内部 256px の 3.75 倍拡大と干渉する
2. **走査線** … `floor(uv.y * uContentSize.y)`（`crt.glsl:78`）。
   224 本を 720 画素に敷くので 1 本 3.21 画素。**本ごとに太さが揺れる**＝うなりが出る

「平面化」は樽型歪み `uCurvature` で、`0` を渡せば `curve()` は素通しになる（シェーダ変更は不要）。

## 2. 設計判断

### 決定 1: 背景の速さは「床速に対する比」で決める

`scroll` に生の UV 値を書くと、`repeat` を変えたときに必ずズレる（BR-01 はこれで起きた）。
値そのものはプロファイルに UV で置いたままにするが、**根拠を `repeat / 8` × 比 で書く**。
比は 3 段しか使わない。

| 比 | 意味 | 使う層 |
|---|---|---|
| 100% | 床と同じ面（第1世代の BG は世界そのもの） | FC far |
| 45% | 手前の層。歩けば明らかに流れる | SFC near |
| 5% | 遠い層。ほとんど止まって見える | SFC far / PS1 far / PS2 far |

### 決定 2: 縦のパララックスは層の**置き場**を動かす（v は動かさない）

UV の `v` をずらすと帯の中で絵が伸び縮み・見切れる。動かすのは `bottom`（層の下端）だけにする。
`BackdropLayer` に `scrollY`（画面比 / m）を 1 つ足し、
`renderer3d` が `bottom - frame.backdrop.verticalOffset * scrollY` を渡す。**シェーダは変えない。**

`bottom` は「カメラ Y = 0 のときの位置」と定義する。area1 の要素は Y が -4.25〜1.75 に収まるので、
基準を 0 に置けば構図が破綻しない。

### 決定 3: 暗室は「空を持たない部屋」として材質が宣言する

暗さの正本を増やさない。既に `dark()` が暗室の材質を 1 か所で作っているので、そこに
`interior: true`（＝空の見えない部屋の材質）を足す。
`gameplay/scene.ts` が読み込み時に「`interior` の材質を含むセクタ」の集合を作り、
毎ティック `sectorAt()` で今いる部屋を引いて `frame.backdrop.brightness` を決める。

- レベルスキーマ（`LevelSector`）に見えの旗を足す案は採らない。§5.9 に反する
- 世代 ID で分岐しない（不変条件 I2）。暗室かどうかは**場所**の話であって世代の話ではない
- 出入りで一瞬に切り替わると目に痛いので、0.25 秒で補間する
- **霧の色にも同じ係数を掛ける**。掛けないと第3世代の暗室で遠景だけが灰色に光る

KV 計画の「どこにも黒が無い」（基準画 F）に対する**唯一の例外**になる。
理由は P2-1 の「何も見えない」が仕掛けそのものだからで、これは §7 に書き戻す。

### 決定 4: ブラウン管の切替は `override` を通すだけにする

シェーダにもプリセットにも分岐を足さない。`PipelineOptions` に
`crtOverride?: () => Partial<CrtPreset>` を通し、UI 側が
`{ mask: 0 }` / `{ curvature: 0 }` を返すだけにする。

走査線のうなり（1.6 の 2 つ目）は uniform では消せないので、**走査線を出力画素基準に丸める**
1 行だけシェーダを変える。これは切替と独立に、常に効かせてよい改善である。

### 決定 5: 設定の置き場は `ui/settings.ts`、操作は当面キー

T3-06 の設定画面はまだ無い。画面を先に作ると本計画が T3-06 を巻き取ってしまうので、
`ui/settings.ts` に**状態と保存だけ**を実装し、操作はキー（未使用の `N` / `F`）に割り当てる。
一覧は `playtest_hud.ts` の操作表に 2 行足す。T3-06 で画面へ移すときは、この状態をそのまま読む。

### BR-01 第1世代の遠景（`profiles.ts:423`）

```ts
far: { texture: 'backdrop_far.png', repeat: 2, scroll: 0.25, scrollY: 0.143,
       bottom: 0.25, height: 0.571 }
```

- `repeat: 2` … 128px の絵が画面 256px にちょうど 2 枚。**テクセルと画面画素が 1:1** になり、
  ドットが割れない（今の 3 は 1 テクセル = 0.67 画素で、拡大縮小の滲みが出ている）
- `scroll: 0.25` … `repeat / 8` そのもの＝床と同速
- `scrollY: 0.143` … `1 / 7` そのもの＝床と同速。第1世代の BG は世界と同じ面である、という宣言
- `bottom: 0.25`（= 56/224）… 画素境界に乗せる。今の 0.26 は 58.24px で境界に乗っていない
- `height: 0.571`（= 128/224）… 縦も等倍。絵の縦を潰さない

絵（`backdropFar`）は**手続きを 1 つのまま**、セットごとに「どの桁に塊を立てるか」を
色表の隣にデータとして持たせる。第1世代は 8 桁のうち 2 桁だけ立て、残りは空にする
（「たまに建物が見えるくらい」）。両端は透明のまま＝繋ぎ目は今と同じ手で消える。

> 縦を床と同速にすると、高い足場に登ったとき城壁が画面下へ沈む。**面として正しい**挙動だが、
> 画面で見て沈みすぎるようなら `scrollY` だけ 0.07（50%）に落とす。横は 100% を動かさない。

### BR-02 第2世代の多重スクロール（`profiles.ts:477`）

```ts
far:  { repeat: 2, scroll: 0.0125, scrollY: 0.007, bottom: 0.24, height: 0.34 },
near: { repeat: 2, scroll: 0.1125, scrollY: 0.064, bottom: 0.5,  height: 0.42 },
```

- 床速 0.25 に対して **5% と 45%**。速度比は 3.4 倍 → 9 倍になる
- `near` の `repeat` を 1.5 → 2 にして、こちらもテクセルを 1:1 にする
- `scrollY` は同じ比を縦（床速 0.143）に掛けたもの

必要な骨格の追加は 2 つだけ。

1. `FrameBackdrop.verticalOffset`（カメラの高さ、m）。`scene.ts` が `frame.camera.position[1]` を入れる
2. `BackdropLayer.scrollY`（画面比 / m）。持たない世代は 0

任意（画面を見てから採否を決める）: **ラインスクロール**。`far` の `uv.x` に
`sin(vUv.y * k + t) * a` を足すと丘の稜線が波打ち、第2世代の署名がもう一段はっきりする。
uniform 1 個・シェーダ 2 行で足せるが、**採らなくても BR-02 の受け入れ条件は満たせる**。

### BR-03 暗室の背景

1. `Material` に `interior: boolean` を足し、`dark()` が `true` を立てる（`material.ts:116`）
2. `FrameBackdrop.brightness`（0..1、既定 1）を足す
3. `scene.ts` は読み込み時に `interior` の材質を含むセクタ id の集合を作り、
   毎ティック `sectorAt(level, player.position)` の結果で目標値（0 / 1）を決め、0.25 秒で補間する
4. `backdrop.frag.glsl` の最後に `color *= uBrightness;` を足す（2 行）
5. `renderer3d.draw` の霧の色 `currentFog[0..2]` にも同じ係数を掛ける

暗室から見て隣のセクタが明るいのは正しい（部屋の入口）。逆にプレイヤーが暗室にいる間は、
遠くの明るいセクタも同じ暗さになるが、**壁で隔てられているので画面には出ない**。

### BR-04 第3世代のカメラ（`profiles.ts:510`）

```ts
camera: { forward: LOOK_SIDE_ON, distance: 3, height: 1.07, targetHeight: 0.3, lookAhead: 0.8 }
```

- `distance 4.5 → 3` … 画角 55° は固定なので、そのまま **1.5 倍の大きさ**になる
- `height` は `height / distance = 3.2 / 9`（見下ろし角）を保つ値。角度は T2-08 の判断を動かさない
- `lookAhead` は `distance` 未満を保つ（`profiles.test.ts:147` の条件）

`profiles.test.ts:137` の「改訂前の半分」は根拠が変わるので、
検査の意味を「**見下ろし角を変えずに距離だけを詰めた**」に書き換える（角度の比は残す）。

寄せると P1-2 の殻の内側などで手前の面がカメラを覆う可能性がある。`near` は 0.1 なので
抜けはしないが、**各パズルの位置で 1 枚ずつ画を撮って確認する**。

### BR-05 モアレ・平面化

```
モアレ   ON（既定）= プリセットどおり / OFF = { mask: 0 }
平面化   OFF（既定）= プリセットどおり / ON = { curvature: 0 }
```

- `src/ui/settings.ts`: `DisplayOptions`（`moire` / `flatten` の 2 つ、`localStorage` に保存）
- `PipelineOptions` に `crtOverride?: () => Partial<CrtPreset>` を足し、`createCrtPasses` の
  既存の `override` へ渡す（`crt.ts` は変更不要）
- `createMiniLevel` に設定を渡す（`MiniLevelState` には入れない。設定は UI 側の持ち物）
- `main.ts` でキー割り当て（`N` = モアレ、`F` = 平面化）。切替時は `bgm_hud` と同じ形の一時表示を出す
- `playtest_hud.ts` の操作表に 2 行足す
- **走査線のうなり**（1.6 の 2 つ目）は、`crt.glsl` の走査線を出力画素基準に丸める:
  1 本の太さを `round(uOutputSize.y / uContentSize.y)` 画素に固定する。1 行の変更で、
  本ごとの太さの揺れ＝うなりが消える。これはモアレの切替とは独立に常に効かせる

> 報告の「モアレ」がどちらを指しているかは画面で確かめる。蛍光体マスクだけなら `mask: 0` で足り、
> 走査線のうなりも含むなら上の丸めまで要る。**両方入れておけばどちらでも足りる。**

## 6. やらないこと

| やらないこと | 理由 |
|---|---|
| 層を 3 枚以上にする／汎用パララックス | §11.1.1。第2世代の多重スクロールは 2 枚の**速度差**で出す |
| レベルスキーマに暗室の旗を足す | §5.9。レベルは 3D の真実だけを持つ |
| 第2世代のためにジオメトリを足す（丘・街並みの実体） | 決定 1。背景は 1 枚の面のまま |
| 設定画面を作る | T3-06 の仕事。BR-05 は状態と保存だけを置き、画面が来たらそれを読む |
| 走査線そのものを設定で切れるようにする | 品質設定（`off` / `light` / `full`）が既にその役目を持つ |

## 7. 確認が要ること

- **モアレの指すもの** … 蛍光体マスクか、走査線のうなりか。BR-05 は両方入れる前提で書いてあるので、
  実装は止まらない。画面を見て、切替が片方だけで足りるなら削る
- **第1世代の縦スクロール** … 床と同速（100%）で沈みすぎないか。沈むなら 50% に落とす
- **第3世代の距離 3.0** … 寄せすぎなら 3.5 まで戻す。見下ろし角の比は固定のまま動かす
