# 外部プレイテスト手順

area1 を5〜8名に遊んでもらい、第1世代の表現、player の読みやすさ、入力デバイス差を確認する手順です。
氏名や入力列は保存せず、通し番号と集計値だけを扱います。

## 準備

```sh
npm run playtest
```

試遊者ごとに `?tester=01`、`?tester=02` のような通し番号を付けた URL を開きます。
同じネットワークの別PCからも接続できます。開始画面を省く開発確認では `?playtest=0` を使います。

想定する内訳は keyboard 3〜4名、gamepad 2〜4名、合計5〜8名です。開発関係者や、
投影ルールをすでに知っている人は対象から外します。

## 進行

1. 移動、jump、チャンネル切替、restart、hint の操作だけを伝えます。投影や世代特性は説明しません。
2. 15〜20分の通しプレイ中は助言せず、考えていることを声に出してもらいます。
3. 終了画面で、各パズルを「自分の言葉で説明できたか」を進行役が記録します。
4. 「CH 1はどんな世代でしたか」「主人公は見やすかったですか」「操作しにくい点はありましたか」
   を、この順序で尋ねます。「CH 1の良いところ」のような誘導はしません。
5. 終了画面の「記録を保存」で JSON を保存します。時間切れは `Esc` で終了します。

記録の保存を忘れた場合は、同じブラウザの開発者コンソールで `__playtest.saveAll()` を実行します。

## 自動記録

JSON には tester番号、device種別、所要時間、clear有無、各パズルの解決時刻、hint段階、
説明可否、respawn回数、switch回数を保存します。氏名と入力列は保存しません。

## 集計

```sh
npm run playtest:report -- playtest_area1_*.json
```

集計では個人別要約、パズル別の所要時間中央値、keyboard / gamepad の差、respawn、switch、hint段階を出します。
人数が統計検定には少ないため、入力デバイス差は「遅い側が50%以内」を実用上の合格基準とします。

判定項目は次の3つです。

- CH 1の強みを、誘導なしで過半数が言語化できる
- CH 1のplayerを「見にくい」とした人が過半数ではなく、魅力への評価が否定的でない
- どのパズルでも keyboard / gamepad の所要時間差が50%以内

実施後は個人データや生ログを公開せず、人数、実施環境、集計結果、判定だけを
[VALIDATION.md](VALIDATION.md) の「人手評価の状態」へ反映します。
