# キービジュアルに寄せるグラフィックス改修計画（KV-00〜KV-09）

基準画: [console-chaos-title.png](console-chaos-title.png)（配布用に縮小したものが `public/assets/title/key_visual.png`）

本書は「基準画のような画にする」という要求を、**この実装の構造の上で何をどう変えるか**へ落としたもの。
`Docs/PHASE2_GIMMICK_PLAN.md` の完了後に着手する枠として置く。

> **後継**: KV-00〜KV-09 は実施済み。試作ステージ（area1）の続きの作業は
> [GRAPHICS_STAGE_PLAN.md](GRAPHICS_STAGE_PLAN.md)（SG-01〜SG-11）が引き継ぐ。
> そこでは基準画がステージの絵（`concept/stage-02-emerald-sky-gen-04.png`）に替わり、
> **KV-07「暗いが光る街」は退役する**（第4世代の署名は「落ち影を持つ唯一の世代」へ移る。
> 同計画 §3 の決定 3 と §5.1）。本書の他の決定は変わらない。

前提とする不変条件（**変えない**）:

- I1: 世界の真実は 3D 1 つ。2D は投影であって別の世界ではない
- I2: ゲームロジックに世代 ID の分岐を書かない。参照するのは `GenerationProfile` の値だけ
  （直接分岐してよいのは `generation/profiles.ts` と `render/pipeline.ts` の 2 つだけ。`chaos/no-generation-branch` が検査する）
- §5.9: レベルデータは色も見た目も持たない。**種別 → 見た目**の対応は `render/material.ts` だけが持つ
- §7.1.1: 実機名・商標由来語を作中に出さない（`npm run check:trademark`）
- §11.1.1: 汎用の抽象（マテリアルグラフ、レイヤシステム）は作らない

## 1. 基準画から読み取るもの

基準画は装飾ではなく**仕様**として読む。読み取れるのは次の 7 点。

| # | 要素 | 基準画での現れ方 |
|---|---|---|
| A | 題字 | ブロックで組んだ「Console Chaos」。`Console` が桃、`Chaos` が白 → 青。輪郭に青緑のにじみ |
| B | 主人公 | 桃髪、ハートの意匠。**四人が横に並び、世代ごとに着ているものが違う**（生成り＋赤 / 原色の多い上着 / 灰白 / 黒紺＋青） |
| C | 四つの世界 | **左から右へ並ぶ帯。** 左端＝赤茶のブロックで組んだ城壁 / 次＝空と雲と緑のある積み木の国 / 次＝灰紫の角張った低ポリ / 右端＝深青の結晶と光る門 |
| D | つなぐ光の帯 | 桃〜青の細い光条が題字の下を横切り、四つの世界を貫く |
| E | 浮かぶ断片 | 三角形の破片と立方体の粒。世界の継ぎ目から出ている |
| F | 背景 | **どこにも黒が無い。** 最も暗い上端でも深紺 `#03092c` |
| G | 全体の色 | 桃紫 ↔ 深青の対比。赤と白が差し色 |

> 2026.08.09 に基準画を差し替えた。読み取れる 7 点は同じで、変わったのは**並べ方**（四つの世界が
> 象限ではなく左から右の帯になった）と E の断片の形（パズルのピース → 三角形の破片）。
> 差し替えが持ち込んだ新しい事実は B で、基準画が**世代ごとに主人公の服を描き分けている**（§2 の事実 6 を参照）。

### 1.1 この計画の芯：C は「絵の趣味」ではなく**制約そのもの**である

基準画の四つの領域は、偶然そう描き分けられているのではなく、
`generation/profiles.ts` が既に持っている制約と**一対一で対応している**。
差し替え後の基準画は四つを**左から右の順**に並べており、対応はいっそう明確になった。

| 基準画の領域（左 → 右） | 対応する世代 | それを成立させている既存のプロファイル値 |
|---|---|---|
| 赤茶と生成りだけの城壁。ブロックが大きい | 第1世代 | `maxSimultaneousColors: 25` / `paletteBlockSize: 16` / `paletteMode: 'fixed54'` |
| 明るく色数が多い積み木の国。空と雲がある | 第2世代 | `maxSimultaneousColors: 256` / `paletteBlockSize: 8` / `alphaBlend: true` |
| 灰紫の角張った低ポリ。色が乏しく平坦 | 第3世代 | `depthBuffer: false` / `affineTexture: true` / `vertexQuantize: 2` / `dynamicLight: false` |
| 暗いが結晶と門が光る | 第4世代 | `dynamicLight: true` / `textureFilter: 'linear'` / 640×448 |

したがって本計画は**新しい絵柄を足す作業ではなく、既にある制約を画面に出し切る作業**である。
「第1世代の領域が 2 色しかない」のは手抜きではなく、それが第1世代の姿だから
（CORE_PLAN「新しい世代が最高の体験というわけではなく、それぞれの世代の魅力を伝える」）。

## 2. 機械的に確認した現状

推測で始めないために、実装と実画面から事実を取った（`?playtest=0` で 4 チャンネルを描画して確認）。

| # | 事実 | 根拠 |
|---|---|---|
| 1 | **背景が黒一色。** 空も遠景も存在しない | `src/render/pipeline.ts:200` の `state.clear(0, 0, 0, 1, ...)` が唯一の背景 |
| 2 | **テクスチャは 9 枚しかなく、4 世代がその同じ 9 枚を見る** | `tools/texture_spec.ts`（`stone_floor` / `stone_wall` / `metal_grate` / `shell_plate` / `vine_green` / `vine_yellow` / `pedestal_top` / `mark_glyph` / `enemy_body`） |
| 3 | 9 枚の色は**茶と灰だけ**。桃も赤も青も無い | 実画面。4 チャンネルとも床・壁が同じ茶色 |
| 4 | 材質表は世代を知らず、色は `[1,1,1,1]` 固定 | `src/render/material.ts`。「色はテクスチャ側の真実」（乗算で変えると第1世代の量子化で中間灰に落ちるため） |
| 5 | 画面に出ている世代差は 8 項目のみ | 内部解像度 / 投影 / 色量子化 / CRT 信号 / 頂点量子化 / アフィン UV / フィルタ / 動的ライト |
| 6 | **主人公だけは既に基準画と一致している** | T2-07 / T2-09 / T2-11 の成果。4 世代とも桃髪・赤白の意匠で描けている |
| 7 | 第1・第2世代は**背景とは別の面**にプレイヤーを描いている | `src/render/pipeline.ts` の `sprites[id]`（T2-10 / T2-11） |

### 2.1 差分の要約

> 現状の世代差は「**同じ茶色い世界の、映り方の差**」に留まっている。
> 基準画が要求しているのは「**四つの違って見える世界**」で、差は F（背景）と C（世界の色）にある。

事実 6 の意味は大きい。**基準画のうち B（主人公）は既に達成済み**なので、
残りは背景と世界の色、そして切替の演出に絞れる。

> 差し替え後の基準画は、ここに 1 つ差分を持ち込んだ。四人の主人公が**世代ごとに違う服**を着ている
> （生成り＋赤 / 原色の多い上着 / 灰白 / 黒紺＋青）。実装は 4 世代とも同じ意匠を 4 通りの
> 描かれ方で出しているので、桃髪とハートという identity は一致しているが、服の描き分けは無い。
> **本計画の範囲には入れない**（決定 1「変えるのは色と背景だけ」と、やらないこと「主人公の描き直し」）。
> 取り込むなら別の枠になる。判断は保留し、事実として記録するに留める。

事実 7 の意味も大きい。第1世代の背景を色づけても、**主人公の色は背景に食われない**（面が別）。
T2-10 で「草の上に立つと靴が緑に潰れる」を解いた仕組みが、そのまま今回の前提になる。

## 3. 設計判断

### 決定 1: 形は 1 つのまま。変えるのは**色と背景だけ**

基準画は四つの世界に見えるが、実装では**同じ形を 4 通りの色で見る**ことで成立させる。
レベルのジオメトリ・当たり判定・パズルには一切手を入れない（I1 と、CI の `solvableIn` 一致検査を守る）。

### 決定 2: 世代ごとの見た目は `profiles.ts` の `art` が持つ

I2 を守れる置き場はここしかない。`VideoProfile` の隣に `art: ArtProfile` を足す。

```ts
export interface ArtProfile {
  /** `public/assets/textures/<textureSet>/` のディレクトリ名 */
  textureSet: string;
  /** 背景（BG 面）。層は最大 2 枚。レイヤシステムは作らない（§11.1.1） */
  backdrop: {
    /** 上端と下端の色。同じ値を入れれば単色になる */
    sky: readonly [Rgb, Rgb];
    /** 遠景の層。null は「層を持たない」 */
    far: { texture: string; scroll: number } | null;
    /** 近景の層。多重スクロールを持つ世代だけが使う */
    near: { texture: string; scroll: number } | null;
  };
}
```

### 決定 3: 色は**乗算ではなくテクスチャセットの差し替え**で出す

`material.ts` が明文化している「色はテクスチャ側の真実。`color` は `[1,1,1,1]` のまま」を崩さない。
乗算で色を変えると `tools/check-textures.ts` が保証している
「第1世代の量子化で中間灰に落ちない」が崩れる。

そこで**テクスチャを世代ごとに 1 セットずつ持つ**。9 枚 × 4 世代 = 36 枚。
`tools/make-textures.ts` は絵を手続きとして持っているので、**色表を 4 つ用意すれば 4 セットが一度に出る**
（形と模様は共通の手続き、色だけがセットごとに違う）。
128×128 が中心なので、36 枚でもテクスチャメモリは実機相当の範囲に収まる。

`material.ts` は今までどおり `texture: 'stone_floor.png'` を持ち、**世代を知らない**。
セットのディレクトリを前に付けるのは描画側（`renderer3d` のテクスチャ解決）だけの仕事にする。

### 決定 4: 背景は `Frame` に `backdrop` を足し、シーンの最初に 1 枚描く

`render/frame.ts` の `Frame` に背景の指定を足し、`renderer3d` が**他の何よりも先に**全画面の面として描く。
`pipeline.ts:200` の黒クリアは残す（背景が描かれなかった場合の下地として）。

層は**最大 2 枚**に固定する。多重スクロールを持つのは第2世代だけなので、
汎用のパララックス機構は作らない（§11.1.1）。

### 決定 5: 光の帯（D）は**切替演出**として出す。常設の物体にはしない

帯を世界に置くと形が増え、I1 と当たり判定の話になる。
基準画で帯が意味しているのは「四つの世界を行き来できること」なので、
**チャンネル切替の瞬間に画面を横切る**のがいちばん近い。
既にノイズ混合を持つ `src/render/shaders/transition.glsl` に、桃 → 青の帯の掃きを足す。

光過敏への配慮（GAME_PLAN §13）の `glitchAmount` が 0 のときは、帯も出さない。

### 決定 6: ハートとピース（E）は**紋の語彙**として統一する

既にある `mark_glyph.png` を基準画の意匠（ハート）へ描き直し、
目標・仕掛けの印をこの 1 つの語彙に揃える。**新しい種類の絵は増やさない。**

### 決定 7: 題字（A）は画像をそのまま使う

フォントとして再現しない。キービジュアル 1 枚を開始画面に出す（KV-00、実施済み）。

### 4.1 進める順番

KV-01 → KV-02 → KV-03 を先に通す（骨格）。ここまでで「黒でない背景」と「世代ごとの色」が入り、
基準画との差のうち **F と C の大半が埋まる**。

## 5. 検査（CI で機械的に守るもの）

絵の良し悪しは機械で見られないが、**壊れたことは機械で見られる**。既存の枠に足す。

| 検査 | 追加する場所 | 落ちたときの意味 |
|---|---|---|
| 4 セットが同じ一覧を持つ | `tools/check-textures.ts` | セットの差し替えで穴が空いた |
| 第1世代セットの色が `FC_PALETTE` の宣言どおりの番号へ落ちる | 同上 | 量子化で意図しない色に落ちる |
| 背景専用の色が陰影を受ける絵に置かれていない | 同上 | 明るさを掛けたときに形が消える |
| ツタ 2 本が gen1 で潰れ、他のセットで読み分けられる | 同上 | F-1 が成立しない |
| 第1世代の背景が 16×16 ブロックあたり 3 色 + 抜きに収まる | `tests/golden/backdrop.test.ts` | `maxSimultaneousColors` を超え、主人公の色を食う |

## 7. やらないこと

| やらないこと | 理由 |
|---|---|
| ジオメトリを基準画に寄せる（城・街・岩を作る） | 決定 1。形を変えるとパズルの成立条件に触れる。**色と背景だけで四つの世界を作れる**ことを先に確かめる |
| 汎用のパララックス／マテリアルグラフ | §11.1.1。層は最大 2 枚、材質は薄い表のまま |
| 主人公の描き直し | 事実 6。既に基準画と一致している |
| 題字のフォント化 | 決定 7 |
| 光の帯を常設の物体にする | 決定 5 |
| 基準画の完全再現 | 基準画は 1 枚絵であって、遊べる画面ではない。**寄せるのは色・明暗・密度の設計**であり、構図ではない |
