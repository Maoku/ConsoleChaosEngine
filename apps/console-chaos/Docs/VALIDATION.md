# Console Chaos 検証結果

生のキャプチャや作業ログに依存せず、現在の設計判断と公開に必要な検証結果をまとめます。

## 技術ゲートと予算

2026-08-01 の技術検証で、投影ルール、GL wrapper、三角形予算の3ゲートを通過しました。

- 第3世代は1フレーム20,000三角形を上限とする。radix sort の2.0 ms推定値146,761三角形に対し、
  最低スペックを3〜5倍遅いと見積もって余裕を確保した上限
- 第4世代は80,000三角形を上限とする
- 第1世代の color crush は0.69 msだった2-pass方式を採用し、1-pass案は採用しない
- 2D / 3D 投影切替時は Z anchor 方式、走査線 sprite の優先順は登録順を採用

後続の OT12 実装では20,000三角形が median 0.187 ms / p95 0.598 msとなり、2.0 ms予算を満たしました。

## ステージと描画量

2026-08-10 の area1 検証では、世界72要素、装飾180要素、player 1体の合計6,516三角形でした。
カリング後の実描画量は次のとおりです。

| 世代 | 三角形 | 予算比 |
|---|---:|---:|
| 第1世代 | 6,243 | — |
| 第2世代 | 6,309 | — |
| 第3世代 | 6,800 | 20,000の34% |
| 第4世代 | 11,065 | 80,000の14% |

同じ場所を固定54色、RGB555、霧と低彩度、実測色の4通りで描き分けます。昼の空、雲の奥行き、
草の天面、道、植生、滝、遠景、浮遊物、門、環境光を4世代で確認し、道の板に描画順の反転はなく、
11件のリプレイも維持されました。

## アセットと sprite

- glTF は [asset-rules.md](asset-rules.md) のサブセットを `check:assets` で検査
- 第1・第2世代の player は256×256 atlas、64 px cell、16 frame、binary alpha の sprite
- sprite は背景と別の面で量子化し、第1世代では背景色と player の3色を取り合わない
- 第3・第4世代は24 bone以内の skinned model を使用
- テクスチャの寸法、色数、alpha、継ぎ目、明度差、4世代の構成は単一の
  `tools/texture_spec.ts` を生成と検査の正本にする

## 音声、描画、回帰

- 同一 score を世代の同時発音能力に応じて3 / 4 / 5 / 6 trackへ編曲
- 世代切替後も拍位置を維持。48 kHz / 14.4秒の確認で無音窓0、peak 0.16〜0.30
- 4世代、切替中間、6パズルの計11描画 command capture と、4世代の PCM fingerprint をテスト fixture 化
- 4世代の半透明、OT12、world/screen sprite を WebGL 2 で確認し、console warning / error は0件
- 商標検査はテキスト、glTF、生成スクリプトを走査し、ロゴや機器固有形状は目視レビュー項目として残す

継続検査は次のコマンドを正本とします。

```sh
npm run verify
```
