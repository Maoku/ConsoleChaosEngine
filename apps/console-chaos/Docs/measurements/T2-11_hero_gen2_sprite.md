# T2-11 第2世代のプレイヤースプライト

第2世代（CH 2）のプレイヤーを、低ポリゴンのモデル（`player.gltf`）から**コマ送りの絵**へ
差し替えた記録。素材は `Docs/hero-gen-2-animations/`（外部で生成した右向き側面図）。

第1世代で同じことをした [T2-09](T2-09_hero_sprite.md) の続きにあたる。
**この項の主題は「もう 1 枚作った」ことではなく、変換も検査も世代で分けずに済ませたこと**にある。

---

## 1. なぜ第2世代も絵にするか

第2世代は第1世代より色は増える（固定 54 色 → RGB555）が、
**深度バッファも動的ライティングも持たず、正射影で真横から見る**という条件は変わらない。
この条件でポリゴンのキャラクタを置くと、モデルを作った意味が出るのは輪郭だけで、
陰影は焼き込んだ絵のほうが密度が高い。第1世代で出した結論がそのまま当てはまる。

結果として、世代の差は「密度が上がる」ではなく「**何でできているか**が変わる」ところに寄る。

| 世代 | プレイヤーの実体 | 出どころ |
|---|---|---|
| 第1世代 | スプライト 16 コマ（`hero_gen1.png`） | T2-09 |
| 第2世代 | スプライト 16 コマ（`hero_gen2.png`） | T2-11（本項） |
| 第3世代 | `gen3_character.glb` … 495 三角形 / 24 ボーン | T2-07 |
| 第4世代 | `gen4_character.glb` … 4,754 三角形 / 24 ボーン | T2-07 |

2D の 2 世代が絵、3D の 2 世代がモデル、という並びになった。
`player.gltf`（T1-08）はどの世代からも参照されなくなったが、
`main.ts` の `player` スモークシーンとローダの検査対象としては残している。

## 2. 素材の実測

素材は第1世代と同じ構成（256×256 のセルが 16 枚。歩き 6 / ジャンプ 6 / 手を前に出す 4）。
不透明画素（α ≥ 8）の外接矩形を測った結果は次のとおり。

| クリップ | 外接矩形の中心 x | 足元 y | 身長（px） |
|---|---|---|---|
| walk 1〜6 | 162.5 / 124.5 / 90.0 / 145.5 / 125.5 / 91.0 | 247 / 245 / 248 / 244 / 244 / 248 | 206〜209 |
| jump 1〜6 | 127.0 / 127.5 / 127.5 / 127.5 / 127.5 / 127.0 | 198 / 206 / 216 / 197 / 205 / 194 | 133〜178 |
| hand-forward 1〜4 | 125.5 / 140.0 / 143.0 / 138.0 | 244 / 244 / 244 / 244 | 201 |

**癖は第1世代と一致した。** T2-09 §2 で挙げた 3 点がそのまま成り立つ。

1. **歩きが「その場で歩く」になっていない。** 中心が 6 コマで 71.5px 流れる
   （162.5 → 91.0）。第1世代は 74.5px で、桁も向きも同じ
2. **ジャンプは既に中心で揃っている。** 127.0〜127.5 に収まる
3. **「手を前に出す」は立ち位置が動かず、腕だけが右へ伸びる。** 中心が右へ 17.5px 流れる

したがって `tools/make-hero-sprite.ts` の横位置の測り方（`HorizontalAnchor`）は
第1世代と同じ割り当てでよく、**世代ごとの分岐を入れずに済んだ**。

## 3. 変換

素材には手を入れず、スクリプトの出力を正本とする（asset-rules.md §9 と同じ）。

```bash
npm run make:hero-sprite
```

スクリプトは**両世代ぶんを一度に出す**。処理は T2-09 から変えていない
（横位置の付け直し / クリップ単位の縦位置 / 1/4 への縮小）。
変えたのは素材の場所と出力名を表（`SHEETS`）にしたことだけで、
第1世代の出力は**バイト単位で変わっていない**ことを確認している。

縦の移動量は walk +7px / jump +39px / hand-forward +11px。
第2世代も内部解像度 256×224・32px/m なので、セル 64px = 2m がそのまま乗る（拡大縮小なし）。

### 3.1 出力

`public/assets/sprites/hero_gen2.png`（256×256、4×4 のセル 16 枚）。
セルの割り当ては第1世代と同じ（0〜5 walk / 6〜11 jump / 12〜15 hand-forward）。

変換後の実測（セル内の外接矩形）:

| セル | 中心 x | 足元 y | 身長 |
|---|---|---|---|
| 0〜5（walk） | 31.5〜32.0 | 62〜63 | 51〜52px（1.59〜1.63m） |
| 6〜11（jump） | 31.5〜32.0 | 57〜63 | 32〜44px（1.00〜1.38m） |
| 12〜15（hand-forward） | 31.5〜35.5 | 63 | 50px（1.56m） |

セルの中心は 31.5。歩きの 6 コマがすべて ±0.5px に収まり、§2 の 1 は解消している。

## 4. ゲーム側の割り当て

`generation/profiles.ts` の `PROFILES.SFC.player`。**第1世代と同じ値**を使う
（`heroSprite()` が 2 世代ぶんを作り、違うのはアトラスのファイル名だけ）。

| ゲームのクリップ | 素材 | 刻み | 繰り返し |
|---|---|---|---|
| `idle` | hand-forward の 1 コマ目 | ― | 止める |
| `walk` | walk 6 コマ | 110ms | する |
| `jump` | jump 6 コマ | 115ms | **しない**（末尾で止める） |

刻みは素材の `README.md` が持つ値をそのまま使う。第2世代の `video.animationHz` は 12 だが、
**掛けない**（asset-rules.md §6 との違い。理由は T2-09 §4 と同じ）。

## 5. 描画とスプライト面

描画（`render/renderer3d.ts` の `drawPlayerSprite`）は世代 ID を見ないので、
**触っていない**。`profile.player.kind` が 'sprite' になった時点で経路が切り替わる（不変条件 I2）。

手を入れたのは**面の合成**だけ。T2-10 で「プレイヤーを絵で描く世代は背景と別の面へ描く」
という規則を入れたが、重ねていたのは第1世代の量子化パスだけだった。
第2世代がその規則に入った結果、面は毎フレーム描かれるのに画面へ出ない状態になる。

そこで `quantize_sfc.glsl` に面の合成を足した。**第1世代とは足す理由が違う。**

| 世代 | 面を分ける理由 | 合成の中身 |
|---|---|---|
| 第1世代 | BG は 16×16 ブロックごとに色数が制限され、OBJ は自分のパレットを持つ。混ぜると草の上で靴が緑に潰れる（T2-10） | 面ごとに独立してブロックパレットを選び、最後に重ねる |
| 第2世代 | 色数の取り合いは無い。分かれているのは描画側の都合 | α ≥ 0.5 なら絵、そうでなければ背景。重ねてから同じ量子化を掛ける |

`pipeline.ts` の `quantizePassesFor` は、面が無い世代で面を要求されたらその場で例外にする。
絵が黙って消えるより、`profiles.ts` の宣言との食い違いに気づけるほうがよい。

## 6. 検査

| どこ | 何を見るか |
|---|---|
| `tests/golden/player_sprite.test.ts` | **絵で描く世代すべて**にアトラスの検査（寸法・アルファが 2 値・接地線・立ち姿の身長・歩きの横位置） |
| `tests/golden/player_model.test.ts` | モデルで描く世代が第3・第4世代だけになったこと |
| `tests/golden/palette_sfc.test.ts` | 第2世代の量子化がスプライト面を受け取ること |
| `tests/unit/profiles.test.ts` | 2D の 2 世代が絵・3D の 2 世代がモデルで、絵の 2 世代が別のアトラスを指すこと |
| `tests/unit/pipeline.test.ts` | 面を持つのが絵で描く世代だけであること（既存。対象が 2 世代に増えた） |

`npm run verify` 通過（512 件）。

### 6.1 落とした検査

T2-09 の「待機は歩きのどのコマよりも背が高い」は**第2世代で成り立たない**。
第1世代は歩きが立ち姿より 0.12〜0.22m 低い（膝を曲げる）のに対し、
第2世代は歩きのほうが 0.03〜0.06m 高い（§3.1）。
どちらの素材でも通るしきい値は 0.25m 相当まで緩める必要があり、それでは何も止められない。

意図していた「待機が歩きの途中のコマを指していないこと」は、
**別のコマであること**と**立ち姿の身長が当たり判定 ±0.1m に収まること**の 2 つが引き継ぐ。

## 7. 目視

`window.__chaos.mini` から 1 フレームずつ描いて確認した（手順は
[T2-10_sprite_plane.md](T2-10_sprite_plane.md) §3）。

- 待機・歩き・ジャンプの 3 クリップが出る。足元が床の線に乗る
- 左を向くと絵が左右反転する（素材は右向き）
- 色が RGB555 を通っても分かれて見える（髪の桃色・上着の青・靴の青）。
  第1世代の同じ場面は固定 54 色で赤と白に潰れており、**世代差が絵の側にも出ている**
- 第1世代 ⇄ 第2世代の切替（両方が絵の世代になったのは今回が初めて）で例外は出ない

## 8. 未確認・残っているもの

1. **世代間の身長差。** 立ち姿は第1世代 1.59m / 第2世代 1.56m でほぼ揃うが、
   第3世代（`gen3_character.glb`、1.5m）へ切り替えるところに段差が残る。
   T2-09 §7 の 3 と同じ項目で、絵どうしの段差は今回で消えた
2. **歩行中の半画素ずれ**（T2-09 §7 の 2）。第2世代は `moveSnap` が 0 なので、
   第1世代（0.25 = 8px 刻み）より板がテクセル格子から外れやすい。
   目視では滲みを認められなかったが、動かし続けたときの見えは測っていない
3. **素材のコマ間の体の大きさ**。第2世代の歩きは立ち姿より 3px（約 6%）背が高い。
   素材側の `character-scale-profile.json` は 8% までを許容範囲としており、
   その中に収まっている。ここを詰めるなら素材の生成側の仕事になる
