# T0-18 世代をまたぐ BGM の位相同期 — 検証記録

| 項目 | 値 |
|---|---|
| 日付 | 2026-08-01 |
| 機材 | Apple Silicon Mac（darwin 25.5.0） |
| 対象コード | `src/audio/clock.ts` / `engine.ts` / `synth_fc.ts` |

## 1. 設計

曲の位置（位相）を**世代から独立した 1 か所**（`MusicClock`）で持つ。
基準は `AudioContext.currentTime`。ゲームループのティックではないため、
描画が落ちても曲は乱れない。

世代切替時にすることは 2 つだけ：

1. 鳴っている音を止める（音源が変わるため）
2. 予約済み位置を現在位置まで巻き戻し、新しい音源で予約し直す

`MusicClock` は触らない。したがって**位相は原理的にずれない**。

## 2. 検証結果

### ヘッドレス（`tests/unit/audio.test.ts`、CI で常時実行）

| 検査 | 結果 |
|---|---|
| 音源を差し替えても同じ audioTime のティック位置が一致する | 通過 |
| 4 世代を往復（FC→PS1→FC→PS1）しても小節位置が一致する | 通過（誤差 1e-9 以下） |
| 曲データを別編曲へ差し替えても位相が動かない | 通過 |
| 先読みスケジューラが同じ音を二重に予約しない | 通過 |

### 実ブラウザ（Chromium / WebGL2 と同じ埋め込み環境）

実際の `AudioContext` と FC 音源で 12 回の切替を行い、小節位置を追跡。

| 検査 | 結果 |
|---|---|
| `AudioContext.state` | `running` |
| 小節位置の単調増加（切替をまたいで巻き戻らない） | 通過 |
| 12 回切替後の位置 | 0 → 0.144 小節（時間経過どおり） |

### 音源そのもの（OfflineAudioContext による波形検証）

| pulse2（デューティ 50%） | 660Hz | 1320 |
| triangle | 110Hz | 221 |

## 3. 未了：4 ブラウザでの確認（受け入れ条件の一部）

IMPLEMENTATION_PLAN §8.1 T0-18 は **Safari を含む 4 ブラウザでの確認**を求めている。
本環境で使えるのは Chromium 系のみのため、**Safari / Firefox / Edge は未検証**である。

対策として、以下は実装済み：

- `PeriodicWave` の生成失敗時に `'square'` へ退避する経路（Safari の既知の差異）
- `AudioContext` の生成をエンジン外に置き、ユーザー操作後に生成する構成にできる
  （自動再生制限への対応。ブートストラップ側の責務）

**残作業（フェーズ 1 の T1-16 までに実施）**：

1. Safari で `PeriodicWave` が期待どおり鳴るか（退避経路に落ちていないか）
2. Safari の `AudioContext.currentTime` の分解能と、`suspended` からの復帰時の位相
3. Firefox / Edge での先読み 0.12 秒が十分か（不足なら `LOOKAHEAD_SECONDS` を上げる）

## 4. 所見

- 先読みは 0.12 秒。長くすると切替の反映が遅れるため、
  「切替の即応性」と「音の途切れにくさ」のトレードオフになる。
  本実装では切替時に予約位置を巻き戻すことで、遅れを 1 回分に抑えている
- 同時発音数は音源側が申告する（FC は 5）。engine は世代を知らない
