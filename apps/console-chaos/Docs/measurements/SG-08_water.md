
## 2. UV は頂点シェーダで送る

`ps1_vertex.glsl` に `uniform vec2 uUvScroll` を足し、`aUv` へ加えてから
`vUvW` / `vUvCorrect` を作る。

**フラグメント側でずらしてはいけない。** アフィン UV は `uv * w` を補間してから `w` で
割り戻す仕掛けなので、割り戻した後にずらすと**第3世代の歪みそのものが動いてしまう**
（滝が流れるのではなく、面が波打って見える）。頂点で加えれば、送った後の UV が
そのまま補間に乗るので、歪みは面の形どおりに固定される。

`material.test.ts` に「`ps1_vertex.glsl` が `uUvScroll` を持ち、
`ps1_forward.glsl` は持たない」を機械的な検査として置いた。

> **uniform はプログラムに残る。** 送らないものには毎回 `[0,0]` を渡し直す
>（`NO_UV_SCROLL`）。渡し忘れると、滝を描いた直後の面が一緒に流れる。
> 影の板・回る面・スプライト・プレイヤーの 4 か所で明示的に 0 を渡している。

## 3. 半透明にしない

`translucent: false` のままにした。半透明にすると、加算合成を持たない第1世代で
**描かれなくなる**（`scene.ts` の「消える 3 条件」の 3 番目）。

滝は世代ごとに消えていいものではない。抜き（`alphaCutoff: 0.5`）だけで水の帯を出せば、
第1世代でも第4世代でも同じ位置に同じ形で落ち続ける。
`water_fall.png` は上下が繋がる（`seamlessY`）ので、UV を送り続けても継ぎ目が出ない。

## 4. 三角形ソートを壊していない

第3世代のリプレイ（`p1_2_sort_break.replay.json`）を含む **11 件がそのまま通る**。

滝は `polygonSort` を持たないので三角形の並べ替えに入らず、
UV の送りは頂点の位置に触れないため、ソートの入力（重心の深度）も変わらない。

## 5. 実測

| | 値 |

| 要素数 | 232 → **238** |
| 三角形（第4世代・カリング前） | 10,069 → **10,117**（6 × 8 = 48） |

`frame.timeSeconds` を 0 と 1.0 に置いて描き比べ、`readPixels` で数えた。

| 画面の領域 | 変わった画素 |
|---|---|
| 上部（空。浮遊する立方体がいる） | 2,999 |
| **下部（地平より下。立方体はいない）** | **101** |

下部で変わっているのは滝だけである（雲も草も動かない）。
UV の送りが実際に画面へ出ていることの担保になる。
