## 1. 何を直したか

改訂前の本編は、要素の見た目を `mini_level.ts` の `TYPE_COLORS`（4 種）と
2×2 のほぼ白いテクスチャ 1 枚だけで作っていた。残り 10 種は既定の灰色に落ちる。

材質・陰影・重ね合わせで表現されるはずの世代差が
「貼る模様が無いので何も起きない」状態になっていた（計画 §2.4）。
ここで作ったのは、その 2 つの穴（**材質表**と**模様**）を塞ぐ最小の層である。

`material.ts` が持つのは 8 項目だけで、シェーダグラフも材質の継承も持たない
（GAME_PLAN §11.1.1「汎用抽象は取り除く対象になる」）。

| 項目 | 何のためにあるか |
|---|---|
| `role` | 5 群（背景 / 足場 / 仕掛け / 敵 / 目標）の区別 |
| `color` | テクスチャに掛ける係数。原則 [1,1,1,1]（§4 の理由） |
| `texture` | 貼る模様。第3世代のアフィン歪みが見えるかはここで決まる |
| `uvScale` | ワールド単位あたりの繰り返し数。0 は面いっぱいに 1 枚 |
| `model` | プロップモデル名。null なら分割つきの箱（T1-23 で埋める） |
| `translucent` | 半透明で描く（T1-25） |
| `castShadow` | 落ち影を作る（T1-26） |
| `polygonSort` | 三角形単位ソートの対象（T1-27） |

## 2. 画像をどう用意したか（§9.4 からの変更・記録）

計画 §9 は「生成画像を発注し、届いた PNG を正本にする」前提だった。
実際には**画像生成の手を用意できなかった**ため、方針を変えている。

> §9.1 / §9.2 の制約（平坦・直線・限られた色数・淡色禁止・シームレス・寸法）を
> **描画手続きとして書き**（`tools/make-textures.ts`）、その出力を
> `public/assets/textures/` に置いた。

この変更の意味は 2 つある。

1. **再現性は強くなった。** §8.1 が心配していた「誰も作り直せない成果物」が生じない。
   モデルと同じく「スクリプトが正本」に戻り、`npx tsx tools/make-textures.ts` で何度でも再生成できる
2. **§9.4 の割り切り（画像だけ PNG を正本とする）は不要になった。**
   ただし `check-textures.ts` による制約検査はそのまま残す。手続きで描いても
   「第1世代で灰色に落ちる色」は普通に書けてしまうため、検査の価値は変わらない

絵としての質は、発注した画像より確実に劣る。
**差し替える場合は §9.2 の発注仕様（下表の「発注の主旨」列）をそのまま使えばよく**、
`make-textures.ts` を消して PNG を置き換えても検査は同じように通る。

## 4. 色の選び方（T1-08 §4 の続き）

第1世代の 54 色パレットには**低彩度の茶・青灰が 1 色も無い**。
そのため「石らしい落ち着いた茶」を素直に置くと、明度 1.0 で中間灰
（152,150,152 / 84,84,84）へ落ち、形が消える。T1-08 でプレイヤーの顔色に起きたことと同じ。

対応として、全色の彩度を上げた。`check-textures.ts` は次の 2 つを機械的に見る。

| 検査 | 落第の条件 |
|---|---|
| 中間灰への落下 | 明度 1.0 / 0.7 / 0.4 のどれかで、無彩色かつ明度 40 以上の色になる |
| 色相の移動 | 有彩色として残ったものどうしの色相が 45° を超えて動く |

暗く沈んで黒に近づくのは系統の変化ではないので数えない（実機でもそう見える）。

### F-1 のツタ 2 本

「CH 2 以降では明確に別の緑・CH 1 では完全に同一色」は、
**総当たりで色を選んで**成立させた（`tools/make-textures.ts` の `VINE_GREEN` / `VINE_YELLOW`）。

探索の条件は「明度 1.0 / 0.7 / 0.4 の**すべて**で同じパレット番号へ落ちること」。
その制約の中で色相差が最大になる組が次の 2 色で、差は **60°** ある。

| | 葉 | 蔓 | CH 1 での落ち先（明度 1.0 / 0.7 / 0.4） |
|---|---|---|---|
| ツタ A | rgb(50,134,88) 色相 147° | rgb(6,82,46) | (40,114,0) / (40,114,0) / (8,58,0) |
| ツタ B | rgb(84,152,0) 色相 87° | rgb(34,82,0) | (40,114,0) / (40,114,0) / (8,58,0) |

この探索の結果として、2 本は**青みの残る深緑**と**黄緑**になった。
「濃い緑と黄緑」という発注の意図からはやや外れるが、
54 色パレットの中で「別の色に見えて、かつ必ず同じ 1 色へ潰れる」組は
この付近にしか存在しない。**F-1 の成立を優先した。**

ゴールデンテスト（`tests/golden/material.test.ts`）が
形状の一致・CH 1 での全画素一致・CH 2 での不一致を固定している。

**KV-03 以降、この探索は不要になった。** テクスチャがセットに分かれたので、
第1世代のセットでは 2 本に同じ色を入れ、それ以外のセットでは別の色を入れればよい。
「第1世代のパレットが 2 本を区別できない」ことを、色の総当たりではなく表で直接書ける
（詳細は `KV-03_texture_sets.md` §2.4）。

## 5. 隣り合う要素の明度差

色相だけの差は第1世代で消える（T1-08 §4）。次の組に、量子化後の明度差 20 以上を要求する。

| 組 | 明度差 | 理由 |
|---|---|---|
| 床 ↔ 壁 | 29 | 面が接する |
| 床 ↔ 装置 | 29 | 橋・スイッチが床の上にある |
| 床 ↔ 敵 | 51 | 敵は床に並ぶ |
| 床 ↔ 刻印 | 63 | 刻印は床に埋まっている。影が落ちても紛れない差が要る |
| 床 ↔ 台座 | 48 | 台座は床の上にある |
| 殻 ↔ 台座（核） | 67 | 裂け目から核が覗いたときに区別できる |

数値は改訂前（1 セット時代）のもの。**KV-03 以降は 4 セットそれぞれで下限 20 を検査する**
（第1世代のセットは量子化後、他の 3 セットは生の明度で測る）。実測値は `KV-03_texture_sets.md` §3。

- **模様は用意できたが、貼る面がまだ 8 頂点の箱**である。アフィン歪みは
  1 面あたり 2 三角形分しか出ない。面の分割は T1-22

- 実際に「CH 3 と CH 4 で UV の歪みが画素差として測れる」ことの確認は、
  描画経路を移した T1-24 のあとに行う（本タスクの受入条件のうち、測定はそこへ送る）
