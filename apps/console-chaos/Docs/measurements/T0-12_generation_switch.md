# T0-12 (V7) 世代切替のパイプライン差し替え — 検証記録

| 項目 | 値 |
|---|---|
| 日付 | 2026-08-01 |
| 機材 | Apple Silicon Mac（darwin 25.5.0） |
| ブラウザ | 埋め込み Chromium（Claude Code Browser ペイン）、WebGL2 |
| 対象コード | `src/render/pipeline.ts` / `shaders/transition.glsl` / `src/debug/smoke_switch.ts` |
| 検証シーン | 同一の 3D シーン（床 + 縦パネル）を 4 世代の経路で描く |

## 1. 同じシーンが 4 世代で異なって見えるか

| ファイル | 世代 | 経路 |
|---|---|---|
| `t0-12_generation_FC.png` | 第1世代 | 256×224 / 正射影 / 54 色 + 16×16 カラークラッシュ / CRT(RF) |
| `t0-12_generation_SFC.png` | 第2世代 | 256×224 / 正射影 / RGB555 / CRT(コンポジット) |
| `t0-12_generation_PS1.png` | 第3世代 | 320×240 / 透視投影 / 頂点量子化 + アフィン UV / CRT(S 端子) |
| `t0-12_generation_PS2.png` | 第4世代 | 640×448 / 透視投影 / 深度バッファ + バイリニア / CRT(コンポーネント) |

シーン側のコードは `GenerationProfile` の値だけを見ており、**世代 ID による分岐を持たない**。
投影方法・解像度・フィルタ・量子化・CRT のすべてがプロファイル経由で変わる
（不変条件 I2 / I5 がコード上で成立していることの実地確認）。

## 2. 切替時にシェーダコンパイルが走らないこと（V7 の受け入れ条件）

`createPipeline()` の最後で `sealShaderCompilation()` を呼び、
以降のコンパイルを例外にしている。実測（GL 呼び出しを差し替えて計数）：

| 計測項目 | 4 世代を巡回しながら 240 フレーム |
|---|---:|
| `compileShader` の呼び出し | **0** |
| `linkProgram` の呼び出し | **0** |
| `createFramebuffer` の呼び出し | **0** |

単体テストでも、パイプライン生成後の `createProgram` が例外になることを固定している
（`tests/unit/pipeline.test.ts`）。

## 3. 切替を連打しても 60fps を維持するか

毎フレーム世代を切り替え（＝**常に 2 世代を描画してブレンドする最悪ケース**）、
240 フレームを実測。各フレーム末尾で `readPixels` により GPU 同期しているため、
実際のゲームループより悲観的な値になる。

| 指標 | 値 |
|---|---:|
| 中央値 | 1.8ms |
| p95 | 5.8ms |
| 最大 | 9.4ms |

16.6ms の予算に対し最大でも 9.4ms。**切替連打でも 60fps を維持できる。**

## 4. 実装上の決定

- **世代の出力先は 2 枚だけ**（現世代・旧世代）。4 世代分を常時持つ必要はない
- 切替中の合成は専用パス `transition.glsl` が担当。走査線ごとの横ずれと明滅で
  「チャンネルが切り替わる瞬間」を表す。位置や形は飛ばさない
  （世界そのものは変わっていないと伝えるため）
- 乱れの強さは `glitchAmount` で 0 にできる（光過敏への配慮、GAME_PLAN §13）
- CRT 品質 Off のときも必ず 1 パス（`present`）を通し、出力先が空にならないようにした

## 5. 申し送り

- 現在のシーン描画は検証用の直接描画。ゲーム本体では `render/frame.ts` の
  描画コマンドバッファ（T1-01）を経由し、`gameplay/` は経路を知らないままになる
- トランジションの尺（350ms / 強制 600ms）は `switcher.ts`（T1-03）が管理する。
  本検証では debug 側に暫定の実装を置いている
