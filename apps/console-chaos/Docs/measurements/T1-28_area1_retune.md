## 4. C：保留した調整と、その理由

### 4.1 通路の起伏（T1-15 §5 の申し送り）

「通路が一直線で起伏が無い」への対応は**保留した**。

床の高さを変えると、**8 件のリプレイ記録がすべて無効になる**。
リプレイは今回の改修（T1-21〜27）が中核ルールを壊していないことを保証している唯一の仕組みで、
それを試遊の前に自分から捨てるのは順序が逆になる。

計画自身も T1-28 を「調整 2 日 + 日程」と**ひとまとめ**にしている。
起伏は「どこで迷ったか」を見てから入れる方が、当てずっぽうに入れるより確実に効く。

### 4.2 敵の寸法

F-2 の敵は 0.5m 角・奥行き 4m の板で、**通路の床そのものを兼ねている**
（消えた隙間から落ちて下の部屋へ入る、という作り）。
見た目としては小さく読みにくいが、大きさを変えると
「消えると落ちる」という F-2 の成立条件そのものが変わる。

**見た目の都合でパズルの成立条件を動かさない。** 再試遊で
「敵だと分からなかった」が実際に出たら、そのときに形を変える。

## 5. 再実施の手順（T1-20 のキットのまま）

```bash
npm run playtest          # ビルドして配布用サーバを立てる
npm run playtest:report -- Docs/measurements/playtest/*.json
```

手順の本体は [T1-20_playtest_kit.md](T1-20_playtest_kit.md)。今回の追加は 1 つだけ。

> 終了画面で、パズルごとに「何が起きたか説明できたか」を**進行役が押す**。
> 押し忘れると `explained` が `null` のままになり、集計の分母から外れる。

判定の順序：

1. **説明できた割合**（所見 2・3 が解けたか）
2. G1-1（第1世代の強みを自発的に言語化できるか）— 記録シート
3. G1-2（CH 1 のキャラが読みやすく魅力があるか）— 記録シート
4. G1-3（入力デバイスによる差）— `playtest:report` が判定する
