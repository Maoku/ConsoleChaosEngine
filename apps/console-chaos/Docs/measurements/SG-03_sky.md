## 1. 4 世代の空

基準画の要求は「天頂が濃い青、地平へ向かって淡い。**昼**」（上位計画 §1 の A）である。
改訂前は第4世代だけが夜、第1世代が紅紫、第3世代が灰紫で、**世代ごとに違う場所**だった。

上位計画 §3 の決定 3 は世代差を「場所の差」から「**映り方の差**」へ寄せ直すことなので、
4 世代とも同じ 1 つの昼の空を見る。**割れるのは出し方のほうである。**

| 世代 | 上端 | 下端 | 出し方 |
|---|---|---|---|
| 第1世代 | `[72,152,232]` | 同じ | 固定 54 色の 27 番（`FC_PALETTE.skyDay`）。上下で色を変えない |
| 第2世代 | `[16,112,224]` | `[104,192,248]` | 実測値を **RGB555** へ丸めたもの。縦のグラデーションはこの世代の署名 |
| 第3世代 | `[120,134,170]` | 同じ | 「最遠のメサ」。**色が乏しいことがこの世代の姿**で、霧の色でもある |
| 第4世代 | `[21,116,229]` | `[105,196,253]` | **実測値そのまま**。丸めも代用もしないのはこの世代だけ |

出どころは `src/render/key_palette.ts` の `KEY_COLORS.skyDay` / `skyHorizon` / `mesaFar` の
3 つだけで、profiles.ts に空の 16 進数は 1 つも無い。
第2世代の丸めは `rgb555()` という 1 行の式で、丸めた値を書き写していない
（書き写すと `key_palette.ts` と 2 つの正本ができる）。

### 1.1 第1世代の空を上下で分けない理由

グラデーションは 16×16 のブロックあたり 3 色 + 抜きという制限を食う。
空が 2 色を取ると、遠景（メサ 3 色）と合わせて番号が 5 つになり、
`backdrop.test.ts` の「背景が固定 54 色の 3 色 + 背景色に収まる」が落ちる。
実測は **空 1 + メサ 3 = 4 番号**でちょうど収まっている。

### 1.2 第3世代の空にだけ下限がある

既存のゴールデン「第3世代の遠景には空より 40 以上明るい色が無い」が掛かっており、
判断 C の gen3 変換を通した `backdrop_far` のいちばん明るい色は **明度 141.0**（実測）。
`mesaFar` の明度は **134.0** なので差は **7.0** で、下限の内側に大きく余裕がある。

空の上端が明度 101 を下回るとこの検査が落ちる。
灰紫（改訂前の `stone`、明度 80.5）へ戻すと落ちる、ということでもある。

### 1.3 4 世代の代表色は互いに異なるままである

| 世代 | 代表色（上端と下端の平均） | 明度 |
|---|---|---|
| 第1世代 | `[72,152,232]` | 140.0 |
| 第2世代 | `[60,152,236]` | 134.0 |
| 第3世代 | `[120,134,170]` | 134.0 |
| 第4世代 | `[63,156,241]` | 137.9 |

同じ昼でも 4 つに割れる。**明度ではもう分かれない**のがこの改修の性質で、
第4世代を「暗い世代」として測る検査が成り立たなくなった（§3）。

## 2. 層の repeat と scroll（判断 H）

SG-01 で背景の絵が 128→256 幅になったので、**4 世代とも repeat と scroll を半分にした**。
層が画面に占める幅と流れる速さは変わらない。

| 世代 | repeat | scroll | scrollY | bottom | height |
|---|---|---|---|---|---|
| 第1世代 far | 2 → **1** | 0.25 → **0.125** | 0.143 | 0.5 | 0.5714 |
| 第2世代 far | 2 → **1** | 0.0125 → **0.00625** | 0.007 | 0.24 | 0.34 |
| 第2世代 near | 2 → **1** | 0.1125 → **0.05625** | 0.064 | 0.5 | 0.42 |
| 第3世代 far | 1.5 → **0.75** | 0.006 → **0.003** | 0 | 0.26 | 0.3 |
| 第4世代 far | 2.5 → **1.25** | 0.008 → **0.004** | 0 | 0.14 | 0.44 |

これで既存のゴールデンが 3 つそのまま通る。

- 2D 世代のテクセルと画面画素が 1:1（`repeat × 幅 = internalWidth` → 1 × 256 = 256）
- 第1世代が床と同速（`scroll = repeat / 8 = 0.125`、`scrollY = 1 / 7`）
- 第2世代の 2 層の速度比 9 倍（0.05625 / 0.00625）

**この 3 点は SG-01 と同じ差分に含めた。** 絵が 256 幅になった瞬間に落ちる検査なので、
分けて置くと途中の状態が赤くなる。

## 3. 差し替えたゴールデン 2 件の理由

| 廃止した検査 | 廃止の理由 | 引き継ぎ先 |
|---|---|---|
| 「第4世代の背景は第3世代より暗い」 | **4 世代とも昼になったので、暗さで世代差を測れない。** 第4世代の代表色の明度は 137.9 で、第3世代の 134.0 より明るい。この検査を残すと「第4世代だけ夜」へ戻す圧力になる | SG-09 の「落ち影を落とすのは第4世代だけ」（`video.dynamicLight` が真な世代とちょうど一致することを見る。世代 ID は書かない） |
| 「第4世代の遠景に空より 120 以上明るい窓がある」 | **遠景が街からメサへ変わり、窓という要素が無くなった。** 実測の差は 73.2 で、遠景をどう描いても 120 は出ない（メサは空と同じ明度帯にある） | SG-10 の「門の光が空より 120 以上明るい」（画面でいちばん明るいものは門になった。上位計画 §1 の I） |

どちらも**検査の意図は残している**。1 つ目は「第4世代に他と違う署名がある」、
2 つ目は「画面のどこかに空より圧倒的に明るいものがある」で、
署名を担うものが背景から光と影へ移っただけである。

引き継ぎ先が入るまでの間、この 2 つは検査されない状態になる（SG-09 / SG-10 で塞ぐ）。

### 3.1 代わりに足した 2 件

| 足した検査 | 何を守るか |
|---|---|
| 4 世代とも昼の空になっている（上端の明度 > 90） | 「世代 = 場所」へ戻っていないこと（上位計画 §3 の決定 3） |
| 空を実測値のまま出せるのは第4世代だけ | 4 世代が**同じ空を 4 通りに出している**こと。他の 3 世代が `skyDay` と一致しないことも同時に見る |
