# KV-02 背景（BG 面）の骨格

計画は `Docs/GRAPHICS_KEY_VISUAL_PLAN.md` の KV-02（決定 2 と決定 4）。
改訂前の背景は `render/pipeline.ts` の黒クリア 1 つだけで、**空も遠景も存在しなかった**。
基準画の F「どこにも黒が無い。どの領域も奥にまだ何かある」をここで満たす。

## 2. 素案から変えたところ（判断の記録）

### 2.1 層に置き場の 2 項目を足した

計画 §3 の決定 2 の素案は `far: { texture, scroll } | null` の 2 項目だったが、
これだけでは**層を画面のどこに置くか**が決まらない。
第2世代の雲は画面の上、第3世代の岩の稜線は下に来るので、
`bottom`（下端の位置）・`height`（厚み）・`repeat`（横の繰り返し数）を足して 5 項目にした。

層の枚数は 2 枚のまま固定する。可変にする仕組み（レイヤシステム）は作らない（§11.1.1）。

### 2.2 `fogDensity` を `ArtProfile` に足した

KV-06 の「遠景が背景色へ抜ける（フォグ色 = 背景色）」は、背景だけでは出せない。
色は `backdrop.sky` の下端をそのまま使うので、プロファイルが持つのは**濃さだけ**にした。
画素ごとの色の混ぜであり、三角形の並べ替えには触れないので、
深度バッファを持たない第3世代でも描画順は壊れない（KV-06 で実装）。

### 2.3 世代ごとの色を `Frame` に持たせなかった

`Frame` に入れたのは横のずらし量 1 つだけで、色と層の指定は `ArtProfile` 側に残した。
描画側は `draw(profile, frame)` で両方を受け取るので二重に運ぶ必要が無く、
**ゲーム側（`gameplay/`）が世代の絵を知る**構造を避けられる（§4.2 の依存方向）。

### 2.4 ずらし量は「ワールドの X」ではなく「画面の右」で測る

構図（`CameraProfile.forward`）が世代ごとに違う。ワールドの X をそのまま渡すと、
通路の奥（+X）を向く第4世代で背景が横に流れない。
視線を Y 軸まわりに 90° 回した向き（`forward = [0,-1]` なら +X、`[1,0]` なら +Z）へ
射影しておけば、どの構図でも「画面の右へ n m 動いた」の意味が揃う。

```ts
frame.backdrop.offset = camera.position[0] * -forwardZ + camera.position[2] * forwardX;
```

## 3. 背景に陰影を掛けない理由

`backdrop.frag.glsl` はライティングを一切持たない。
第1世代の白と生成りは、明るさ 0.7 を掛けると中間灰へ落ちて形が消えるため（KV-01 §2）。
**平らな 1 枚だからこそ 54 色表の最上段を置ける。**

## 5. 実画面での確認

`?playtest=0` で 4 チャンネルを 1 フレームずつ描き、出力の上端（画面中央 x、上から 40px）を
`readPixels` で読んだ値。CRT パスの減光が乗るので、プロファイルの値そのものにはならない。

| 世代 | 読んだ色 | 空の宣言 |
|---|---|---|
| 第1世代 | 86, 10, 49 | 160, 20, 100 |
| 第2世代 | 14, 77, 128 | 24, 136, 232 |
| 第3世代 | 77, 61, 88 | 88, 72, 104 |
| 第4世代 | 7, 8, 39 | 8, 8, 40 |

**4 世代とも黒でなくなり、互いに違う色になった。**
第1世代ではプレイヤーの絵が背景に食われていないことも画面で確認した
（スプライト面が別なので、桃の髪と赤い上着がそのまま出る。T2-10 の仕組みがそのまま効く）。

## 6. 検査

`tests/golden/backdrop.test.ts` が 6 件。

1. 4 世代の空の色を数値で固定
2. どの世代の空も黒でない（基準画 F）
3. 4 世代の背景色が互いに異なる（**落ちたら今回の改修の主目的が壊れている**）
4. 層は最大 2 枚。近景だけを持つ状態を禁じる
5. 第1世代の背景が `FC_PALETTE` の色だけを使う
6. 世代ごとにテクスチャセットが分かれている（KV-03 の前提）
