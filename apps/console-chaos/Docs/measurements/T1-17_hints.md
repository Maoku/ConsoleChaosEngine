## 1. 受け入れ条件（IMPLEMENTATION_PLAN §8.2）

| 条件 | 判定 | 根拠 |
|---|---|---|
| 4 段階が動作する | **満たす** | 3 分 / 2 分 / 2 分で段階 1・2・3 が自動提示。段階 4 は要求時のみ |
| 完全にオフにできる | **満たす** | `hints: { enabled: false }`。オフの間はタイマーを回さない（テストで確認） |

## 2. 待ち時間（§16.1-e でフェーズ 3 に調整する値）

`HINT_DELAYS_MS = [180_000, 120_000, 120_000]`（0→1 / 1→2 / 2→3）。
**コードに数値を埋め込まず、この 1 か所だけを持つ。** 調整はここを書き換える。

段階 4（解法の直接提示）は `requestHint` からしか到達しない。
自動提示のコードパスを持たせていない（GAME_PLAN §13.1）。

## 3. 「同一パズルでの経過時間」の測り方

滞在時間は **未解決のパズルの中心から `HINT_ENGAGE_RADIUS`（10m）以内にいる間だけ**進む。
エリア 1 は部屋を 16m 間隔で並べてあるので、隣の部屋のパズルを数え始めない。
離れれば止まり、別のパズルへ移れば表示は消える（段階は保持する）。

パズルの中心は、レベルデータの `puzzles[].entities` の平均位置から作る。
配置を動かせば判定も自動で追従する。

## 4. 文面（§13.1「答えではなく見る場所を示す」）

| 段階 | 内容 | 例（F-1） |
|---|---|---|
| 1 | 全パズル共通 | この場所には、別の世代でしか見えないものがある |
| 2 | 対象世代（**レベルデータから組み立てる**） | CH 1 で見てみよう |
| 3 | 使っている制約 | 色の選択肢が少ない世代では、近い色どうしが同じ 1 色として扱われる |
| 4 | 解法 | CH 1 では 2 本のツタが同じ色に潰れ、装置が間に橋を架ける。橋を渡って台座へ |

- 段階 2 以降のチャンネル名は `requiredGenerations` から生成する。
  文面に世代を直書きしない（レベルを直したときに嘘にならない）
- 段階 1〜3 に操作の動詞（触れる・踏む・渡って…）が出ないことをテストで機械的に検査している
- 実機名は出さない（CH 1〜4 / 第1〜4世代のみ）。`check:trademark` の対象

## 5. 表示

HUD の下帯（CRT フレームの外側）に `ヒント n／4 <本文>` と、
その下に「ヒントを見てもクリア記録は変わらない」を出す（§13.1 のペナルティ無しの明示）。
ブラウザ実測での表示内容:

```
ヒント 1／4 この場所には、別の世代でしか見えないものがある
ヒントを見てもクリア記録は変わらない
```
