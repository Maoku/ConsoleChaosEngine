# T2-09 第1世代のプレイヤースプライト

第1世代（CH 1）のプレイヤーを、低ポリゴンのモデルから**コマ送りの絵**へ差し替えた記録。
素材は `Docs/hero-gen-1-animations/`（外部で生成した右向き側面図）。

---

## 1. なぜ絵にするか

第1世代は深度バッファも動的ライティングもアルファ合成も持たず、色は固定パレット 54 色から
ブロック単位で 25 色しか同時に出せない。この条件では、ポリゴンで作ったキャラクタを量子化して
見せるより、**最初から絵として描かれたもの**のほうが実機の見えに近い。

第2〜第4世代は従来どおりモデルで描く。世代差は「密度が上がる」だけでなく
「**何でできているか**が変わる」ところまで出る。

> **追記（T2-11）**：同じ理由が第2世代にも当てはまることが分かり、
> 第2世代も絵へ移した。下の表の第2世代の行は `hero_gen2.png`（スプライト 16 コマ）に読み替える。
> 境目は「第1世代とそれ以外」ではなく「2D の 2 世代と 3D の 2 世代」になった。
> 経緯は [T2-11_hero_gen2_sprite.md](T2-11_hero_gen2_sprite.md)。

| 世代 | プレイヤーの実体 | 出どころ |

## 2. 素材の実測

素材は 256×256 のセルが 16 枚（歩き 6 / ジャンプ 6 / 手を前に出す 4）。
不透明画素（α ≥ 8）の外接矩形を測った結果は次のとおり。

| クリップ | 外接矩形の中心 x | 足元 y | 身長（px） |
|---|---|---|---|
| walk 1〜6 | 167.5 / 125.0 / 93.0 / 163.0 / 133.0 / 93.5 | 250 / 244 / 247 / 250 / 244 / 247 | 180〜188 |
| jump 1〜6 | 128.0 / 128.0 / 127.5 / 127.5 / 127.5 / 127.5 | 202 / 201 / 218 / 197 / 216 / 198 | 139〜182 |
| hand-forward 1〜4 | 137.0 / 146.5 / 153.0 / 152.0 | 246 / 246 / 246 / 245 | 205〜206 |

ここから読み取れた 3 点が、変換の内容をそのまま決めている。

1. **歩きが「その場で歩く」になっていない。** 中心が 6 コマで 74.5px 流れる
   （167.5 → 93.0、167.5 → 93.5）。素材のまま貼るとキャラクタが左右へ滑る
2. **ジャンプは既に中心で揃っている。** 127.5〜128.0 に収まっており、触る必要が無い
3. **「手を前に出す」は立ち位置が動かず、腕だけが右へ伸びる。**
   だから外接矩形の中心が右へ 16px 流れる。ここでコマごとに中心を測ると、
   腕を伸ばすほど体が左へ後ずさりしてしまう

## 3. 変換（`tools/make-hero-sprite.ts`）

素材には手を入れず、スクリプトの出力を正本とする（asset-rules.md §9 と同じ）。

```bash
npm run make:hero-sprite
```

### 3.1 横位置

外接矩形の中心をセルの中心へ揃える。**どのコマで測るかはクリップによる。**

| クリップ | 測り方 | 理由 |
|---|---|---|
| walk | コマごと | 手足が前後へ等しく振れるので中心が体の中心の近似になる |
| jump | コマごと | 同上。素材が既に揃っているので移動量は全コマ 0px になった |
| hand-forward | 先頭コマの値を全コマへ | 片腕だけが伸びるため。§2 の 3 |

### 3.2 縦位置

縦は値そのものに意味がある（歩きの上下動、ジャンプの浮き）。コマごとには動かさず、
**クリップの中でいちばん深い足がセルの下端に来るよう、クリップ全体を同じ量だけ動かす。**
移動量は walk +5px / jump +37px / hand-forward +9px。

結果として**セルの下端が接地線**になる。描画側はこれを前提に、板の下辺を足元へ合わせる。

### 3.3 縮小

1 ワールド単位 = 32 画素（`level/schema.ts`）なので、セル 64px = 2m。
第1世代の内部解像度は 256×224 で、正射影の縦の可視範囲が 7m なので、
**セル 64px が画面の 64px にそのまま乗る**（拡大縮小が入らない）。

透明部分に残った色が輪郭へ滲まないよう、乗算済みアルファで 4×4 を平均してから戻す。
被覆率が半分に満たない画素は抜く。第1世代に半透明は無いので、
出力のアルファは 0 か 255 しか持たない。

### 3.4 出力

`public/assets/sprites/hero_gen1.png`（256×256、4×4 のセル 16 枚）。
16 コマがちょうど 4×4 に収まり、asset-rules.md §7 の上限 256×256 に収まる。

| セル | 中身 |
|---|---|
| 0〜5 | walk 1〜6 |
| 6〜11 | jump 1〜6 |
| 12〜15 | hand-forward 1〜4 |

変換後の実測（セル内の外接矩形）:

| セル | 中心 x | 足元 y | 身長 |
|---|---|---|---|
| 0〜5（walk） | 31.5〜32.0 | 61〜63 | 44〜47px（1.38〜1.47m） |
| 6〜11（jump） | 31.5 | 58〜63 | 35〜45px（1.09〜1.41m） |
| 12〜15（hand-forward） | 31.5〜35.0 | 63 | 51px（1.59m） |

セルの中心は 31.5。歩きの 6 コマがすべて ±0.5px に収まっており、§2 の 1 は解消している。

## 4. ゲーム側の割り当て

`generation/profiles.ts` の `PROFILES.FC.player`。

| ゲームのクリップ | 素材 | 刻み | 繰り返し |
|---|---|---|---|
| `idle` | hand-forward の 1 コマ目 | ― | 止める |
| `walk` | walk 6 コマ | 110ms | する |
| `jump` | jump 6 コマ | 115ms | **しない**（末尾で止める） |

- **待機**：素材に待機のクリップは無い。「手を前に出す」の 1 コマ目が腕を下ろした立ち姿なので、
  そこで止めて待機にした（第4世代が歩行の 1 コマ目を立ちポーズに使うのと同じ手）。
  身長 51px = 1.59m で、当たり判定の 1.6m とほぼ一致する
- **ジャンプ**：6 コマ × 115ms = 0.69 秒。滞空はこれより長くなり得るので、
  繰り返すと着地の直前に踏み切りの絵が出る。末尾のコマで止める
- **刻み**：`video.animationHz`（第1世代は 6Hz）は**掛けない**。あれはボーンアニメの
  コマ落ちを再生時刻の量子化で作るための値で（asset-rules.md §6）、
  スプライトは素材そのものが既にコマの列になっている。素材が持つ間隔をそのまま使う
- **手を前に出す の 2〜4 コマ目**は、今どのクリップからも参照していない。
  ゲーム側のクリップは idle / walk / jump の 3 つしかなく、攻撃に絵を割り当てるには
  `PlayerClip` を 4 世代ぶん増やす必要がある（第2〜第4世代のアセットに対応する
  クリップが無く、3 つの偽の対応を作ることになる）。素材の記録としてアトラスには残した

## 5. 描画

`render/renderer3d.ts` の `drawPlayerSprite`。板 1 枚をカメラの方へ立てるだけ。

- **コマ送りはセルごとの板を選ぶだけで済ませた。** UV を焼き込んだ板を起動時に
  16 枚作っておく。シェーダにも毎フレームのバッファ書き換えにも手を入れていない
- **左右反転**は X を負にスケールして行う。素材は右向きなので左を向くときだけ裏返る。
  面の向きも裏になるため、この 1 枚だけ間引きを切る
- **陰影は掛けない**（環境光 1.0 / 拡散 0）。絵には既に陰影が焼き込まれており、
  立体として照らすと平らな板だと分かってしまう
- 世代 ID は見ていない。`profile.player.kind` が 'sprite' か 'model' かで経路が分かれる（不変条件 I2）
