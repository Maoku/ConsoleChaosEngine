## 1. 足した材質

3 つとも `props_vine`（交差する 2 枚の板・8 三角形）に絵を貼るだけである。
実機の草木と同じ作り方で、半透明合成を持たない第1世代でも抜きで成立する。

| 種別 | 絵 | 大きさ（`transform.scale`） |
|---|---|---|
| `tree` | `tree_pine.png` | `[0.5, 1.0, 0.5]`（幅 1m・高さ 2m） |
| `bush` | `foliage_tuft.png` | `[0.375, 0.375, 0.375]` |
| `flower` | `foliage_tuft.png` | `[0.25, 0.25, 0.25]` |

**房は茂みと同じ絵で、大きさだけが違う**（絵を増やさない）。
どれも `decoration: true` / `alphaCutoff: 0.5` / `uvScale: 0`。

## 2. 置いた数

**87 個**（木 21・茂み 34・房 32）。要素は 72 → 159 になった。
`id` の頭を `decor_` で揃え、ファイル末尾にまとめてある（R-4）。

| セクタ | 個数 |
|---|---|
| `start` | 11 |
| `f1` | 12 |
| `p1_1` | 16 |
| `s1` | 13 |
| `f2` | 12 |
| `p1_2` | 16 |
| `goal` | 7 |
| `p2_1` | **0** |

並びは足場ごとに固定の式（`(区画 × 7 + 桁 × 3 + 側 × 5) % 6`）から作っている。
同じ入力から同じ絵が出る（不変条件 I4）。散布アルゴリズムでも配置ルールでもない
（§8 のとおり、自動配置ツールは作らない）。

### 2.1 計画との差：暗室には置かない ⚠

実装計画の SG-06 は「**8 セクタすべてに置く**」だったが、`p2_1` には 1 つも置いていない。

`p2_1` は P2-1 の暗室である。`Material.interior` によって背景の明るさが 0 へ落ち、
「何も見えない」ことが仕掛けそのものになっている（BR-03）。
SG-04 で `causeway` に天面の草を生やさなかったのと同じ理由で、
**空の見えない部屋に草は生えない**。7 セクタに置いた。

## 3. 見つけた不具合：板に貼る絵が上下逆になる

画面で確かめたところ、木が**逆さまに生えた**（葉が下・幹が上）。

原因は貼り先の UV である。`props_vine.gltf` は板の上端（y = +1）に `v = 0` を割り当てており、
`renderer3d` は `flipY: true` でテクスチャを読む（画像の最初の行が `v = 1`）。
**画像の上端が板の下端に来る。**

| 貼り先 | 上下 |
|---|---|
| 背景の層（`backdrop.frag.glsl`） | 画面の上が `v = 1`。`flipY` と噛み合って上下そのまま |
| 箱の面 | 敷き詰める絵なので上下に意味が無い |
| **交差する 2 枚の板（`props_vine`）** | **`v = 0` が板の上端。ここだけ絵が裏返る** |

納品素材は 14 枚とも「見えるとおり」に描かれている（木は上が葉、下が幹）ので、
`import-textures.ts` の取り込み表に `flip` を足し、**板に貼る 8 枚だけ上下を入れ替えて**取り込む
（`tree_pine` / `foliage_tuft` / `cloud_bank` / `water_fall` / `gate_glow` /
`vine_green` / `vine_yellow` / `enemy_body`）。

> モデル側の UV を直すほうが筋である。`props_vine.gltf` は
> `tools/blender_export_props.py` の出力なので、直すには Blender が要る。
> 絵の側で吸収するほうが、正本（スクリプト）と出力の対応を崩さない。
