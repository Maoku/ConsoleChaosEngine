# T2-01〜06 ギミック改訂の記録

ギミックレビュー（F-1 / F-2 / S-1 / P2-1）への対応。計画は `Docs/PHASE2_GIMMICK_PLAN.md`。
4 件の設計判断はすべて承認済み（同 §6）。

## 1. 着手前に測った事実

| 事実 | 値 | 出どころ |
|---|---|---|
| 跳べる幅（実効） | **4.8 m** | 滞空 2×8.2/22 = 0.745 秒 × 最高速 5.5 m/s + 体幅 0.7 m |
| 改訂前 F-1 の谷 | 2.0 m | `f1_floor_a`(〜21) / `f1_floor_b`(23〜) |
| 改訂前 S-1 の谷 | 4.0 m | `s1_floor_a`(〜52) / `s1_floor_b`(56〜) |
| 改訂前 P2-1 の影の濃さ | 平均 **0.21** | `caster_hint.png` のアルファ平均 0.30 × `SHADOW_STRENGTH` 0.72 |
| 改訂前 P2-1 の塊 | 3 × 4 × 4 m の**透明な実体** | `p2_1_caster` の当たり判定に `solid: false` が無かった |

**「渡れてしまう」の原因はギミックではなく谷の長さだった。**
改訂後の谷は F-1 が 7 m、S-1 が 8.5 m、F-2 が 11 m。いずれも 4.8 m に対して十分な余裕がある。

## 2. 世代差の出し方（改訂後）

| パズル | 成立条件（プロファイル値のみ） | 解ける世代 |
|---|---|---|
| F-1 | `paletteMode === 'fixed54'`（撚られる）**または** `projection === 'perspective3d'`（糸を選べる） | FC / PS1 / PS2 |
| F-2 | `0 < spritesPerScanline < 12`（群れがあふれる） | FC |
| S-1 | `affinePlane && alphaBlend`（面が回る × 踏み台が見える） | SFC |
| P2-1 | `dynamicLight`（松明を持つ） | PS2 |

世代 ID による分岐はどこにも書いていない（不変条件 I2、ESLint `chaos/no-generation-branch` が検査）。

### F-1 は「1 つの規則」から 3 通りの遊びが出る

規則は **「黄緑のツタは体重で切れる。緑は保つ」** だけ。

| 世代 | 投影 × パレット | 結果 |
|---|---|---|
| CH 1 | 2D × 潰れる | 装置が 2 本を撚る → 太い 1 本、揺れない → **簡単** |
| CH 2 | 2D × 潰れない | 奥行きが潰れていて糸を選べない → 黄緑が受け持ち 0.5 秒で切れる → **渡れない** |
| CH 3 / CH 4 | 3D | 緑（Z = +1.25）を選べる。ただし細く、±0.5 m で揺れる → **難しいが可能** |

ツタの Z 間隔は 2.5 m。プレイヤーの半幅 0.35 m に対し、揺れの最小位置でも
Z = 0 のまま歩くと乗れない（`f1_thin_vine_fall.replay.json` が固定している）。

## 3. 総当たり対策（決定 3）

正解ルートを持つ 2 部屋は、**試行ごとに正解が変わる**。
`attemptSeed = hash32(seed, 復帰回数)` から毎ティック引き直す（状態を持たない ＝ ずれようがない）。

| 部屋 | 取りうる正解 | 検算 |
|---|---|---|
| F-2 | 10 枚中 4 枚を 1〜3 歩幅で選ぶ道 = **45 通り** | `routeOf` は 200 種の種すべてで行き止まりを作らない |
| P2-1 | 6 枚 × 5 レーンの隣接歩き = **200 通り超** | `causewayOf` は隣との差が必ず 1 レーン以内 |

リプレイは種を記録する（`ReplayRecord.seed`）。同じ記録からは同じ道が出る（不変条件 I4）。

## 4. 描画側の変更

| 変更 | 内容 |
|---|---|
| 陰影の uniform 化 | シェーダ直書きの `0.45 + 0.55 * lambert` を材質の `ambient` / `diffuse` にした。既定値は同じなので**既存の見た目は変わらない** |
| 松明（点光源） | `uTorch`（xyz = 位置、w = 半径）。`dynamicLight` を持つ世代でだけ w > 0。暗室の材質は `ambient 0.05 / diffuse 0` なので、松明の届く範囲以外は文字どおり見えない |
| 落ち影 | 平行光 → **点光源投影**。近いほど大きく伸び、伸びた分だけ薄くなる。テクスチャのアルファをやめて単色にした（改訂前は実効 0.21 で読めなかった） |
| 回る面 | `frame.plane`（中心・角度・半径）。中心はレベルが置いた印（`s1_pivot`）そのもの。角度はパズルと同じ `planeAngleAt(tickIndex)` から出すので、面の模様と島の位置がずれない |

## 6. 画面での確認について（未実施）

**この改訂は、まだ人の目で見て確かめていない。** 作業環境のブラウザは
`requestAnimationFrame` が止まる（描画枠が隠れている）ため、キャンバスが黒のままになる。
改訂前のコードでも同じなので**この改訂による不具合ではない**が、
「回る面が本当に画面全体で回って見えるか」「暗室で松明の輪が読めるか」は確認できていない。

確認は `npm run dev` を実行し、次の URL を手元のブラウザで開いて行う:

```bash
npm run dev
```

- `/?scene=mini&level=puzzle_lab` … 6 部屋を並べた検証用レベル（部屋ごとに近い）
- `/?scene=mini&level=area1` … 本編
- `C` キーで当たり判定の可視化、`1`〜`4` でチャンネル切替

見るべき点は §7 の 3 つ。

## 7. 積み残し

- **絵はまだ既存のテクスチャを流用している。** ツタの綱・導きの灯・松明の光の輪は
  専用の絵を起こしたほうがよい（計画 T2-06 の「追加 3 点」）。今は
  石床・格子・刻印のテクスチャで代用しており、意味は通るが読みやすさは上がる余地がある
- **回る面の見え方**：画面全体が回ることの気持ちよさと、乗り移りの猶予
  （12 秒周期・接近は約 2 秒）は実際に触って調整する必要がある
- **暗室の暗さ**：環境光 0.05 と松明の半径 7m が「怖いが理不尽ではない」範囲かは要調整
- **ツタの揺れ**：振幅 0.5m・周期 4 秒が CH 3 / CH 4 で「難しいが可能」に収まっているか
- 再プレイテスト（T2-07）は未実施
