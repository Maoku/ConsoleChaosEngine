## 1. レベルの構成（3D の真実のみを持つ）

| 要素 | 位置（x, y, z） | 役割 |
|---|---|---|
| 出発点の足場 | (-3.5, -0.25, 0) | スタート地点 |
| **2D 専用の橋** | (0, -0.25, **-4**) | XY 投影では隙間を埋めるが、3D では 4m 奥にある |
| 到達点の足場 | (3.5, -0.25, **-5**) | ゴールのある足場 |
| **3D 専用の道** | 壁 (2.5, 1.2, **+4**) | 2D では Z 無限の柱として通れない。3D では奥を通れる |
| ゴール | (5.2, 0.6, -4.6) | 到達点の足場の上 |

**クリアには両方のモードが要る。** 2D でしか橋を渡れず、3D でしか壁を越えられない。

## 2. 自動での通し確認（ヘッドレス操作）

| シナリオ | 結果 |
|---|---|
| 3D のまま右へ歩き続ける | 橋が無いので落下（y = -2.63）。**2D 専用の橋が「3D では存在しない」ことが挙動で分かる** |
| 2D へ切り替えて右へ歩く | 奥の橋が床の続きになり渡れる。x = 1.65 で壁に阻まれて停止（**2D では手前の壁が通れない**） |
| 渡り切った状態で 3D へ戻す | Z が 0 → -4 へ吸着（トランジション中の中間値 -0.19 を観測）。接地は維持される |
| 3D で壁と同じ XY・違う Z に立って 2D へ切替 | x = 2.5 → 1.65 へ押し出される。安全座標への復帰は発生せず |
| 通しクリア | 2D で橋 → 3D へ戻る → 壁を迂回 → ゴール接触で `cleared = true` |

## 4. ゲート G0-1 の状態：**未判定（人による検証が必要）**

IMPLEMENTATION_PLAN §8.1 の G0-1 は
「T0-15 のミニレベルを**開発者以外 2〜3 名**に触ってもらい、
説明なしで橋の意味を理解できるか確認する」ことを求めている。

自動で確認できるのは「ルールが意図どおり動くこと」までであり、
**「直感的に理解できるか」は人にしか判定できない。**

### 触ってもらう際に見るべき点

1. 3D で落ちたあと、自分から 2D へ切り替えて橋を渡ろうとするか
   （＝「2D では見え方が変わる」に自力で気づくか）
2. 2D で壁に阻まれたとき、3D へ戻って回り込もうとするか
3. 2D → 3D の切替で Z が吸着する動きを見て、「奥へ引き寄せられた」と理解できるか
   （説明なしで「ワープした」「バグった」と受け取られないか）
4. 空中で 3D に戻すと落ちることを、理不尽と感じないか

3 が破綻する場合、§5.5.3 の Z アンカー方式そのものの見直しが必要になる。
1・2 が破綻する場合はレベルの誘導（配置・視線）の問題であり、
コンセプトの再設計までは要さない可能性が高い。

## 5. 実装上の申し送り

- 本ミニレベルの物理は最小実装（1 軸ずつ移動して押し戻す）。
  スイープによる連続衝突判定は T1-06 で入れる
- 入力は debug 用の直接読み取り。抽象化された入力層は T1-04
- 接地している間だけ安全座標を更新している。これにより
  「3D → 2D で詰んだら直前に立っていた場所へ戻る」が自然に成立する
