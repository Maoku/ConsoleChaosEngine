## 1. 何を足したか

基準画の B（3 つの深さにある雲）と H（空に散る小さな立方体）である。
**回廊が空に浮いていること**を、足元の雲と空の浮遊物の 2 つで示す。

| 種別 | 絵 | 形 | 大きさ | 個数 |
|---|---|---|---|---|
| `cloud` | `cloud_bank.png` | `props_vine`（交差する 2 枚の板） | `[3, 0.75, 3]` | 54 |
| `sky_cube` | `stone_wall.png` ＋ 天面 `grass_top.png` | 分割つきの箱 | `[0.25, 0.25, 0.25]` | 19 |

雲は足場の **6m 下**、立方体は **5〜9m 上**に置いた。どちらも装飾（`collider` を持たない）。

### 1.1 立方体は足場と同じ材質でできている

基準画の浮遊する立方体は、よく見ると**足場そのもの**である（草の載った岩の塊）。
そこで新しい絵もモデルも足さず、足場の材質に `decoration` と `float` を立てただけにした。
**語彙を増やさない**（§11.1.1）。`material.test.ts` が
「`sky_cube.texture` と `platform.texture` が一致する」で固定している。

## 2. 動きは材質が 1 項目だけ持つ

```ts
float: number;   // 上下する振幅（m）。0 は動かない
```

位相は**要素の位置**から作る（`sin(t · 1.0 + x · 0.7 + z · 1.3)`）。
同じ入力から同じ動きが出るので、リプレイが壊れない（不変条件 I4）。

**`gameplay/` はこれを知らない。** `frame.positions` は書き換えず、
`renderer3d.ts` の `drawItem` がモデル行列を作るときに Y を足すだけである。
物理も投影もパズルも、立方体が動いていることに気づかない。

## 3. 動きの強さは 1 か所から配れる

`Renderer3dOptions.motionAmount?: () => number`（既定 1）を足した。
`PipelineOptions.glitchAmount` と同じ形にしてあるので、T3-06 で光過敏の設定画面を作るときに
1 か所から両方へ配れる（`src/ui/a11y.ts` は現在まだ空のファイルで、設定の本体は無い）。

`motionAmount() === 0` で立方体は完全に止まる。
SG-08 の滝の UV 送りにも同じ係数が掛かる（片方だけ掛け忘れると
「動きを止めた」のに滝だけ流れ続ける）。`material.test.ts` が機械的に見る。

## 4. 実測

| | 値 |
|---|---|
| 要素数 | 159 → **232**（雲 54 + 立方体 19） |
| 三角形（第4世代・カリング前） | 9,409 → **10,069** |
| 内訳 | 雲 54 × 8 = 432 / 立方体 19 × 12 = 228。合計 **+660** |

実装計画 §6 の見積り（雲 30 個 240 + 立方体 20 個 240 = 480）より 180 多い。
雲を 30 枚では足元が埋まらなかったので 54 枚に増やしたぶんで、
予算（第3世代 20,000）に対しては依然 50% 前後である。

## 5. 画面で確かめたこと

`window.__chaos` で `frame.timeSeconds` を 0 と 3.0 に置いて 2 枚描き、`readPixels` で比べた。

- **2,520 画素が変わる**（691,200 画素中）。立方体だけが動いている
- 空の立方体は側面が砂岩・天面が草で、足場と同じ見た目になっている
- 雲は足場の下に白い帯として敷かれ、回廊の縁の外側が空へ抜けずに雲で埋まる

`npm run check:levels` は通り、`requiredGenerations` は 1 つも変わっていない。
