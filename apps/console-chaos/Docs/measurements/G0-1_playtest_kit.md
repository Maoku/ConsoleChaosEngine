## 0. このゲートで測るもの

**「2D では奥行きが潰れる」というルールを、説明されずに理解できるか。**

自動テストで確認できるのは「ルールが意図どおり動くこと」までで、

## 1. 進行役の台本（これ以外を言わない）

読み上げてよいのは**操作方法だけ**。画面にも同じ内容しか出していない。

> 「ゲームの試作を触ってもらいます。左のほうから、右奥にある黄色いブロックまで行ってください。
> 操作は画面の左下に出ています。うまくいかないときは自由に試してください。
> こちらからの説明はしません。考えていることを声に出しながらやってもらえると助かります。」

**言ってはいけないこと**（言った時点でこのゲートは無効）:

- 「2D」「3D」「奥行き」「投影」「Z」といった語
- 「チャンネルを変えると見え方が変わる」といった仕組みの示唆
- 詰まっているときの誘導（「1 を押してみて」など）

10 分経っても進まない場合は、そこで打ち切って**「詰まった」として記録する**。
打ち切りも立派な結果であり、ヒントを出して通させると測定にならない。

## 2. 観察項目（T0-15 §4）

| # | 見る点 | 破綻したときの意味 |
|---|---|---|
| 1 | 3D で落ちたあと、**自分から**チャンネルを変えて渡ろうとするか | 「見え方が変わる」に気づけない。レベルの誘導（配置・視線）の問題 |
| 2 | 2D で壁に阻まれたとき、3D へ戻って回り込もうとするか | 同上。往復の必要性が伝わっていない |
| 3 | 2D → 3D で Z が吸着する動きを「奥へ引き寄せられた」と理解できるか。**「ワープした」「バグった」と受け取られないか** | **§5.5.3 の Z アンカー方式そのものの見直し**（§10-A の再決定） |
| 4 | 空中で 3D に戻すと落ちることを、理不尽と感じないか | ルールの一貫性が伝わっていない |

3 が破綻した場合だけ、コンセプト側の設計（Z アンカー）に手が要る。
1・2 はレベル制作で解ける可能性が高い。

## 4. 判定基準（**本書で新たに定める。要確認**）

GAME_PLAN / IMPLEMENTATION_PLAN は G0-1 の合格ラインを数値で定めていないため、
以下を提案する。実施前に合意しておくこと。

| 判定 | 条件 |
|---|---|
| **通過** | 試遊者の過半数が (a) ヒントなしで 10 分以内にクリアし、(b) Q1 または Q2 で「2D だと奥行きが無くなる／平べったくなるので繋がって見える」に相当する説明を**自分の言葉で**できる |
| **条件付き通過** | クリアはできるが説明が出てこない → レベルの誘導を作り直して再試遊（コンセプトは維持） |
| **不通過** | 観察 3 で「バグだと思った」が過半数 → §5.5.3 の Z アンカー方式を見直す（§10-A の再決定。GAME_PLAN §15 のリスク対応へ） |

(b) は言葉の正確さを問わない。「奥行き」「Z」といった語を使う必要はなく、
「ぺちゃんこになるから繋がる」で通過とする。
