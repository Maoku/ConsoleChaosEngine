# T2-10 スプライト面（BG と色の制約を分ける）

第1世代のプレイヤー（T2-09）を背景と同じ 1 枚の絵に混ぜて量子化していたため、
**背景の色数がキャラクタの色を食っていた**。ツタの上に立つと靴が緑に潰れる。
実機と同じく BG 面と OBJ 面を分け、それぞれ独立にブロックパレットを選ぶようにした。

---

## 1. 症状と原因

第1世代の量子化は 16×16 のブロックごとに最頻 3 色を選び、その 3 色 + 画面共通の背景色へ
各画素を丸める（T0-10）。ブロックの中身がキャラクタと背景の混合だと、面積の大きい背景が
最頻色を占める。ツタ（緑）の前に立つと、靴の数十画素は「緑・濃緑・黒」のどれかへ落ちる。

実機はこうならない。**BG の属性ブロックは BG にしか掛からず、OBJ は自分のパレットを持つ。**
背景に何が描かれていても、スプライトの色は影響を受けない。

副作用として、F-1（色の潰れ）の成立条件も揺れていた。プレイヤーが仕掛けの前に立つと
BG のブロックパレットが変わるため、**立ち位置でパズルの見えが変わりうる**状態だった。

---

## 2. 直し方

### 2.1 面を分ける

`render/pipeline.ts` が、プレイヤーを絵で描く世代にだけ**スプライト面の FBO** を持たせる。

```
[BG 面]      … 背景・仕掛け・モデルで描くプレイヤー
[スプライト面] … 絵で描くプレイヤーのみ。α = 0 が「何も描かれていない」
```

- 面の有無は `GenerationProfile.player.kind` が決める（不変条件 I2）。本項の時点では第1世代のみ。
  T2-11 で第2世代も絵になり、同じ規則で面を持つようになった（重ねる理由は世代で違う。
  [T2-11_hero_gen2_sprite.md](T2-11_hero_gen2_sprite.md) §5）
- 面は毎フレーム **α = 0 で塗り潰してから**描く
- 呼び出し側は `pipeline.render(request, drawScene, drawSprites)`。
  `drawSprites` を渡さないスモークシーンでは面が空のまま量子化へ渡り、見えは変わらない

**BG は面ごと残る。** スプライトが上書きしないので、BG のブロックパレットは
「キャラクタがそこに居なかったとき」と同じ値になる。実機で BG タイルが OBJ の裏に
そのまま存在するのと同じで、F-1 の揺れもこれで消える。

### 2.2 パレットを 2 面ぶん数える

第 1 パス（`quantize_fc_blocks.glsl`）の出力を **16×14 から 16×28 へ**広げ、
上段に BG 面、下段にスプライト面のブロックパレットを積む。パス数は 2 のまま。

スプライト面を数えるときは **α < 0.5 の画素を数えない**。数えると「透明」が最頻色になり、
数ドットしかない靴やリボンの色が 3 色の候補から落ちる。

### 2.3 面ごとに候補が違う

第 2 パス（`quantize_fc.glsl`）が面を重ねる。丸め先の候補は面で変える。

| 面 | 候補 |
|---|---|
| BG | ブロックの 3 色 + 画面共通の背景色 |
| スプライト | ブロックの 3 色のみ（残る 1 色は抜き＝透明なので候補に入らない） |

スプライト側に背景色を混ぜると、暗い色の靴が黒へ吸われる。実機の OBJ パレットも
4 色のうち 1 色は透明なので、選べるのは 3 色である。

## 3. 確認

`npm run dev` の CH 1 で、ツタ（`f1_vine_a` / `f1_vine_b`、x = 23.5）の位置に立たせて確認した。

- **改訂前**: 靴が緑一色に潰れる（利用者の報告）
- **改訂後**: 靴の周辺 80×32 画素を `readPixels` で読み、上位 8 色がすべて
  赤系・白系・灰（`209,99,95` / `168,128,126` / `82,24,25` など）。緑は 1 画素も無い

レンガの壁（茶）の前に立つ場合も同様に、キャラクタが茶へ寄らないことを目視した。
第2〜第4世代（モデルで描く側）は描画経路が変わっていないことを、
4 世代それぞれ 1 フレーム描いて確認した。

> **ブラウザでの目視は手で 1 フレーム進めれば行える。**
> 作業環境のタブは `document.hidden` のため rAF が止まるが、
> 開発ビルドが公開している `window.__chaos.mini` から `tick()` / `draw(w, h)` を
> 直接呼べばキャンバスは更新される。`readPixels` での定量確認も同じ経路で通る。
> T2-07 / T2-09 で「目視できない」としていたのは、この入口を使っていなかったため。

## 5. 残っていること

- **スプライトのブロックは 16×16 のまま。** 実機の OBJ は 8×16 ごとにパレットを選べるので、
  本来はもう一段細かい。今の粒度だと横方向の帯が実機より粗く出る。
  細かくするなら第 1 パスの出力を広げるだけで済むが、実機らしさの判断が要るので保留する
- **同時発色数（`maxSimultaneousColors: 25`）は数えていない。** T0-10 から変わらず、
  ブロックあたりの色数だけを制限している
